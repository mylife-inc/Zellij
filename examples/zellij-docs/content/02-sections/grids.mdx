## feature-grid

Equal-weight cards. The workhorse.

```yaml
type: feature-grid
heading: Everything you need
subhead: Included in every plan.
columns: 3                          # 2 | 3 | 4
items:
  - icon: workflow
    title: Workflows
    body: Branches and conditions, no scripting language.
    href: /features#workflows       # optional — makes the card a link
  - icon: shield
    title: Compliance
    body: PCI scope reduction out of the box.
```

`icon` is a [lucide](https://lucide.dev) name in kebab-case. Icons resolve on
the server, so none of the icon library reaches the browser, and an unknown
name fails the build naming the export it looked for.

## bento-grid

Asymmetric tiles. Use it where a few things genuinely matter more than the
others — that is the difference from `feature-grid`, which weights everything
equally.

```yaml
type: bento-grid
heading: One platform, not five tools
items:
  - title: Automations that read like sentences
    body: When a request is approved by finance, open the fulfilment task.
    image: assets/automation.png
    span: large                     # normal | wide | tall | large
    href: /features#workflows
  - title: Roles and rules
    body: Permissions by team, by record, or by field.
    icon: shield
    span: normal
    background: tinted              # per tile
```

Spans are cells on a four-column grid: `normal` is 1×1, `wide` 2×1, `tall` 1×2,
`large` 2×2. On a tablet the grid drops to two columns and `large` becomes
`wide`; on a phone everything is one column.

A tile with an `image` puts it at the foot and lets it fill the remaining
height, which is what makes a `large` tile read as one composition rather than
a card with a picture stuck under it.

## card-carousel

A horizontally scrolling row, snapped, with the next card peeking past the
container edge so the row reads as scrollable before anything moves.

```yaml
type: card-carousel
heading: Why teams pick Acme
subhead: Everything below is in every plan.
link: { label: Browse the guide, href: /guide }   # trailing link on the heading row
cardWidth: medium                                 # narrow | medium | wide
items:
  - eyebrow: Workflows
    title: Route work the way your team already works.
    body: Branches, parallel steps and conditions.
    image: assets/workflows.png
    href: /features#workflows
    background: tinted
```

<Callout type="info" title="The browser does the scrolling">
`scroll-snap` on a plain overflow container, so a trackpad, a touch drag,
shift+wheel and keyboard scrolling all work before any JavaScript runs. The
prev/next buttons are a convenience on top, they disable at each end, and they
hide entirely when the row fits.
</Callout>

The track is focusable so it can be scrolled by keyboard even when the cards
inside are not links.

## pricing-table

One to four tiers.

```yaml
type: pricing-table
heading: Simple pricing
subhead: Per seat, per month.
tiers:
  - name: Free
    price: "$0"
    period: forever
    description: For trying it out.
    features: [Up to 3 users, Community support]
    cta: { label: Start free, href: /guide }
  - name: Team
    price: "$12"
    period: per user / month
    features: [Unlimited users, SSO, Priority support]
    cta: { label: Start a trial, href: /guide }
    highlighted: true
```

Exactly one tier may be `highlighted`. A single "Contact us" tier renders
gracefully — the layout does not assume three.

`price` is free text, so `$12`, `From €9` and `Contact us` all belong. A bare
number is accepted too and stringified, since YAML would otherwise hand it over
as a number.
