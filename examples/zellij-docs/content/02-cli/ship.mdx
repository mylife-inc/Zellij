---
title: zel ship
description: Import into a configured site, build once, then deploy or publish an image.
---

<Callout type="tip" title="Implemented in source">
`ship` imports MkDocs or Docusaurus into a new configured hosted site, then uses
shared delivery to build once and publish. These commands are newer than the
public `zellij-v0.1.3` binary; use a compatible build from source until released.
</Callout>

```bash title="terminal"
zel ship ./old-docs --out ./manual --provider netlify --site-id existing-site-id
```

Set `NETLIFY_AUTH_TOKEN` in your environment first. The site must already exist.
Netlify creates a **draft preview** unless you pass `--prod`. `--site-id` (also
`--site`) overrides `NETLIFY_SITE_ID`. No login or account/site creation runs.

`--out` is required and names the converted site root:

```text
manual/
  zel.yaml
  content/
    site.yaml
    01-guide/
    assets/
```

The original source remains untouched. The destination must be new or empty,
outside the source tree, with neither directory containing the other.

## Publish an image

Choose the contents explicitly and provide the exact registry reference:

```bash title="terminal"
zel ship ./old-docs --out ./manual --image static --tag ghcr.io/acme/manual:v1
zel ship ./other-docs --out ./other-manual --image next --tag ghcr.io/acme/other:v1
```

`static` packages generated HTML with an HTTP server; `next` packages the
standalone Next.js wrapper. Authenticate your container client with the registry
first. Image publication does not also deploy to a cloud provider.

All current import converters emit hosted content. Validation/build therefore
requires a running Docker, Podman or nerdctl runtime and a compatible Zellij
engine image, including for Netlify. Missing or stopped runtimes produce an
error with setup guidance; Zellij does not install or start them. The generated
hosted HTML needs HTTP serving. For Markdown sites that support double-clicking
`index.html`, use the [portable renderer](/cli/build).

## Inspect the conversion first

```bash title="terminal"
zel ship ./old-docs --out ./manual --provider netlify --site-id existing-site-id --dry-run
```

This reads and converts the source in memory, lists proposed files and conversion
warnings, and prints the delivery destination. It writes nothing and performs no
validation, runtime/credential checks, builds or network requests. Ambiguous
format detection requires `--from mkdocs` or `--from docusaurus`.

Warnings about skipped documents, external navigation and unsupported source
features stay visible. Building successfully establishes that the generated
content compiles; review navigation and content to assess migration fidelity.

## After success or failure

The new `zel.yaml` saves the image kind/tag or Netlify site ID, never credentials.
Production intent is not saved: a later Netlify publication defaults to a draft.

```bash title="terminal"
zel check ./manual
zel publish ./manual
# Request live Netlify publication explicitly:
zel publish ./manual --prod
```

Conversion/plan errors stop before writing. Once import completes, any later
runtime, credential, validation, build or delivery failure leaves the converted
site available for review. Fix the failing stage and use the saved site; rerunning
`ship` against the now-populated destination is refused. A failed image push can
be retried with `zel image push <exact-tag>` without rebuilding. If Netlify reports
an uncertain upload result, inspect its dashboard before retrying.

The composed command validates and builds once, then hands that result to the
publication step. No push/upload follows a failed build. It does not create a
persistent local `site/` export; use `zel build ./manual` when you want one.

## Options

| Option | Behavior |
| --- | --- |
| `<source>` | Required external documentation root |
| `--out <path>` | Required new or empty configured site root |
| `--from <format>` | Force the converter instead of detecting |
| `--provider netlify` | Deploy static HTML to an existing site |
| `--image static\|next` | Publish this image kind; conflicts with `--provider` |
| `--tag <reference>` | Required with `--image`; exact registry destination |
| `--site-id <id>` / `--site <id>` | Netlify site ID/domain; overrides environment |
| `--prod` | Netlify production request; conflicts with `--image` |
| `--dry-run` | In-memory conversion and plan only |
