---
title: zel migrate
description: Detect, convert and check in one step, stopping at the first failure.
---

```bash title="terminal"
zel migrate ./old-docs --out ./manual --layout site
# Same command, shorter:
zel mig ./old-docs --out ./manual --layout site
```

This imports into `manual/zel.yaml` and `manual/content/`, then validates the new
hosted site. The original source is unchanged. Both existing converters emit
hosted content, so validation requires a running Docker, Podman or nerdctl
runtime. Zellij reports missing tools without installing or starting them.

For compatibility, **omitting `--layout` still writes raw hosted content directly
under `--out`**. `--layout content` explicitly selects that same legacy behavior.
The shortcut has identical defaults. The layout option is implemented in source
and is newer than the public `zellij-v0.1.3` binary.

## Inspect before writing

```bash title="terminal"
zel mig ./old-docs --out ./manual --layout site --dry-run
```

Dry run converts in memory and prints proposed files, warnings and unmapped
features. It writes nothing and skips validation and runtime checks. Use `--from
mkdocs` or `--from docusaurus` to select a converter when detection is ambiguous.

Conversion errors stop before writing. If a later validation or runtime check
fails, the converted destination remains available for inspection; fix the issue
and run `zel check ./manual`. Rerunning migration into the populated folder is
refused. Destination and source must be disjoint, and the destination must be new
or empty.

## Validation and migration fidelity

The default hosted check validates the content model without compiling the full
Next.js site. Run `zel check ./manual --deep` to parse MDX and check local
references, then `zel build ./manual` to compile the site. A passing check or
build does not establish that every source-tool feature survived; review the
conversion report and navigation.

The converter creates a guide and a minimal landing page. Custom landing pages,
source plugins, and unsupported navigation features still require author review.
See [conversion limits](/cli/convert).

## Options

| Option | Behavior |
| --- | --- |
| `<source>` | Required source documentation root |
| `--out <path>` | Required new or empty destination outside the source |
| `--layout content\|site` | Legacy raw content (default) or configured site |
| `--from <format>` | Force a converter instead of detecting |
| `--dry-run` | In-memory conversion only; no writes or validation |
