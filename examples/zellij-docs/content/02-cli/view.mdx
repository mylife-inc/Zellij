---
title: zel view
description: Build portable or hosted content, serve the static site locally, and open a browser.
---

<Callout type="tip" title="Available in source">
`view` / `v` builds portable Markdown natively or hosted YAML/MDX through the
container engine, then serves the export with the native HTTP server. Portable
previews need no Docker or Node. A default browser opens unless you pass `--no-open`.
Native release packages may lag the source version.
</Callout>

```bash title="terminal"
zel view                         # configured-site discovery
zel v docs/manual                # any configured site folder
zel view ./docs                  # explicit raw Markdown or hosted content
zel view ./docs --port 0
zel view ./docs --watch
zel view ./docs --out ./published-docs --name "Acme documentation" --theme forest
zel view ./docs --no-open --port 8080
zel view ./docs --browser /path/to/browser
```

`view` builds the selected content, prints the actual local URL,
and launches the system's default browser. The server remains in the terminal
until **Ctrl-C**. The output stays on disk. Portable output also works by opening
`index.html` directly; hosted output requires HTTP serving.

## Input and output

A configured site's `renderer` selects portable Markdown or hosted YAML/MDX.
Explicit raw folders are detected the same way as `build`. Portable titles,
navigation, assets, search, themes and rendering limits match
[`zel build --target portable`](/cli/build#portable-markdown).

Hosted previews run the same container engine export as `build --target static`.
The server uses the engine-resolved `basePath` automatically, including nested
prefixes. Files retain the normal flat build layout on disk. A usable Docker,
Podman or nerdctl runtime is required for the build; missing prerequisites fail
with exit code 4 before staging output or opening a server. Run `zel doctor` for
setup guidance. The CLI never installs or starts a runtime for you.

For configured sites, output defaults to `build.out` or `site/` beside `zel.yaml`.
Legacy raw Markdown output defaults to the sibling `<input-folder>-site`. For example,
`zel view ./docs` produces `./docs-site`. Raw hosted content defaults to `./dist`
in the working directory. `--out` can choose another directory
outside the input. It must be new, empty, or a previous Zellij export. A failed
build preserves the previous output and does not launch a browser.

The selected loopback port is reserved before building. If it is occupied,
`view` fails before changing the output. Use `--port 0` for an automatically
chosen free port; the printed URL and browser launch use that actual port.

## Browser behavior

`--no-open` runs the build and server and prints the URL without invoking any
browser launcher. It is useful on remote machines and in automated checks.

`--browser` selects an executable. The URL is passed as one argument, without
a shell. Quote an executable path containing spaces; this option does not
accept a shell command or extra browser arguments. It cannot be combined with
`--no-open`.

If a launcher is missing or exits unsuccessfully, `view` prints a warning and
keeps the server running. Open the printed URL manually. Launching a browser
does not block HTTP responses or Ctrl-C shutdown.

## Editing documents

By default, `view` builds once. Add `--watch` to rebuild after content, configuration
or local asset edits, additions and deletions, and reload open HTTP previews.
Hosted watching performs a full container export each time, which takes longer
than the native portable build:

```bash title="terminal"
zel view ./docs --watch --port 0
zel view ./docs --watch --no-open
```

The initial build must succeed before the server starts. Later build errors are
printed in the terminal and shown as a notice in the preview. The last successful
site remains available. Correcting the source triggers another build; successful
publication clears the notice and reloads the page, preserving its URL, query,
and fragment. Search and navigation are regenerated with the documents. If the
page being viewed is removed, its preview returns 404 and can recover when the
page is restored.

The watcher polls file contents and waits for two matching scans before a full
rebuild. Atomic editor saves, same-size edits, and temporarily missing source
folders are handled. Hidden entries and `node_modules` are ignored. Nested
symlinks and Windows junctions are rejected. All visible regular files are
scanned, so large asset trees cost more to watch; this is not an incremental
compiler. Output must remain outside the source folder.

Reloading requires JavaScript and the running HTTP preview. The reload client
is added only to HTTP responses, never to exported files. Portable output can still
be moved and opened through `file://` with no server or network. Plain `view`
and `serve` do not inject a reload client. Ctrl-C stops the server and watcher,
retains the export, and waits for an in-progress staged build to finish cleanup.
For hosted content this can take as long as the active container build. A cancelled
build is discarded; it never replaces the previous export. If content changes
during a hosted build, its stage is discarded and watch rebuilds the newer input.
An initial build interrupted by edits exits with retry guidance.

A hosted preview pins its initial `basePath`. Changing it while watching reports
an error and preserves the old site. Restore the prefix or restart the command
to use the new URL. Port and output settings also require a restart.

Raw HTML rendering, MDX components, math, and Mermaid retain the portable
builder's documented limits. Changing the name, theme, output, or port options
requires restarting the command. Site name/theme, logo and navigation from
[`zel.yaml`](/cli/config#portable-markdown) are reread on each watched build;
CLI name/theme overrides remain in effect.

## Options

| Option | Meaning | Default |
| --- | --- | --- |
| `[dir]` | Configured site or explicit raw content directory | `./zel.yaml`, then `./docs/zellij/zel.yaml` |
| `--out <path>` | Static output directory | Configured `build.out`/`site/`; raw portable sibling `<input-folder>-site`; raw hosted `./dist` |
| `--name <text>` | Portable site header name | `zel.yaml` name, otherwise input folder name |
| `--theme <name>` | Portable theme from `zel list themes` | `zel.yaml` theme, otherwise `cupertino` |
| `--port <n>` | Loopback port; `0` chooses an available one | `preview.port`, otherwise `3000` |
| `--watch` | Rebuild on source edits and reload the HTTP preview after success | Off |
| `--no-open` | Print the URL without opening a browser | Off |
| `--browser <executable>` | Explicit browser executable | System default browser launcher |

`--json` is currently limited to inspection commands and is rejected before a
view build or server starts.

A versioned preview watches only `content/` and the sibling `zel.yaml`, ignoring
`site/` and other files in the site root. Missing/invalid config and renderer or
layout changes retain the last successful preview and show an error. Restore the
config or restart preview. Port/output settings are fixed until restart.
`--name` and `--theme` are refused for hosted previews. Set hosted presentation
fields in `content/site.yaml`. To serve a retained hosted export later, use
`zel serve --base-path /your/prefix` when its `basePath` is nonempty.
