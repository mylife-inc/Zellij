`zel publish` and `zel deploy` both exit with `not implemented yet`. The common

```bash title="terminal — proposed"
zel publish
zel publish docs/manual
zel pub docs/manual
```

## What it is

`publish` will execute delivery settings saved in the site's `zel.yaml`.
[`deploy`](/cli/deploy) will select a provider explicitly at the command line;
[`ship`](/cli/ship) will import external documentation before delivery. These
operations will share one plan that validates and builds once, then uploads,
pushes an image, or deploys it as requested.

The plan will not invoke a public `build` followed by a public `deploy` that
builds the same site again. Build output is passed to the delivery step.

A proposed configuration for a portable site is:

```yaml title="docs/zellij/zel.yaml — proposed"
version: 1
renderer: portable
name: Acme documentation
publish:
  action: deploy
  provider: netlify
  site: acme-docs
```

Markdown will live under `docs/zellij/content/`, with generated HTML in its
sibling `site/`. Another site-directory name is allowed and is selected with an
explicit path. See [planned configuration](/cli/config#planned-cli-defaults).
These fields are not accepted by the current flat portable config reader.

## What each step contributes

<Steps>
<Step title="Resolve and validate">
Resolve the site, renderer and saved delivery intent. Validate content and
required tools/settings before performing external delivery.
</Step>
<Step title="Build once">
Create the requested static export or container image. Static-server images and
Next.js wrapper images remain distinct packaging choices.
</Step>
<Step title="Deliver">
Upload static files, push an image to a registry, or deploy that image to a
configured provider. Registry-only publication does not require a cloud provider.
Credentials come from the environment or the provider's supported login mechanism.
</Step>
</Steps>

Netlify is the first requested direct deployment integration. Other providers
remain part of the broader proposed catalog. The
[full CLI contract](https://github.com/mylife-inc/Zellij/blob/main/specs/zel-cli-contract-2026-10-18.md)
records the delivery and CI design.

## Until it lands

For an existing Markdown folder, the native CLI can validate and build; use the
Netlify CLI for the upload. This example requires that separate CLI, a configured
Netlify site and its credentials:

```bash title="terminal"
zel check docs && \
zel build docs --out dist && \
netlify deploy --prod --dir dist
```

Each step runs only if the preceding step succeeds. [`zel ci`](/cli/ci) can also
generate an existing Netlify workflow, using its currently documented options.
