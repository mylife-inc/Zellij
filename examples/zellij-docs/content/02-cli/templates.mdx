## Choose a starter

```sh
zel templates
zel templates show book-classic
zel templates --json
```

| Template | Renderer | Direct-file viewing | Contents |
| --- | --- | --- | --- |
| `product-docs` | Portable | Yes | An overview and a short handbook. |
| `product-studio` | Hosted | No | A Cupertino-themed product page with hero, bento and feature sections, plus a guide. |
| `book-classic` | Portable | Yes | Generated title page and contents, cover, preface, part, two chapters and appendix; optional PDF. |
| `book-technical` | Portable | Yes | Blue rules, mathematical prose, numbered equations and proofs; coordinated web/PDF layouts. |
| `book-study` | Portable | Yes | Warm typography, passages, commentary and questions; coordinated web/PDF layouts. |

Book-classic 0.2.0 requires CLI/engine rc.6 or later. Its [book manifest](/cli/books)
drives reading order, metadata and both web and print. PDF is disabled by default:
normal creation, checks and web builds need no container runtime. Enable PDF
with `zel build my-book --pdf` or `pdf.enabled: true`; `zel pdf my-book --check`
checks print compatibility natively. Actual typesetting requires the optional
LuaLaTeX Linux container runtime. The classic print design supports English/LTR;
numeric citations, glossary and subject index are also supported in rc.8.
Multilingual print remains planned. Technical/study editions are included in
rc.8, as described below.
Previously published book-classic 0.1.0 archives remain unchanged.

## Technical and study editions

Candidate rc.8 adds two starters, each at template version 0.1.0. These need
CLI/engine 0.2.0-rc.8 or later.

```sh
zel create my-handbook -t book-technical --name "Reasoning clearly" --set author="A. Writer"
zel create my-study -t book-study
```

The technical edition pairs blue rules and sans-serif chapter titles with serif
reading text. Its manuscript demonstrates a numbered sum, theorem/proof,
invariants, code, citations, glossary and subject index. The study edition uses
warm accents, expressive serif titles and quiet quotation treatments, with
original passages, commentary, questions, footnotes and reference catalogs.
Both include a preface, part, two chapters and appendix. Their title pages are
typographic; an optional local PNG/JPEG cover can be added to the manifest.

Set `book.edition` to `classic`, `technical` or `study` to change the coordinated
web/PDF design without rewriting the content. [Book editions](/cli/books#coordinated-editions)
explains the scope. The original three template archives remain unchanged.

| `creative-studio` | Expressive serif typography, original identity studies and editorial spacing | Studio, Selected work, customization guide |

With an rc.9 source build:

```sh
zel create my-product -t product-launch --name "My product"
zel create my-platform -t software-platform --name "My platform"
zel create my-studio -t creative-studio --name "My studio"
```

Each starter includes two landing pages, two Markdown guide pages and local,
original SVG illustrations. Product-launch demonstrates a keyboard-operated
media accordion; software-platform includes an interface illustration and a
step-by-step workflow; creative-studio expands two fictional project studies.
These are original designs inspired by product storytelling and editorial
layout patterns, not copies of another company's website or assets.

Edit `content/site.yaml` for identity and theme, `content/pages.yaml` for the
section order, and `content/sections/` for the content. The included guide explains
artwork replacement, color modes, motion, navigation and the optional separate
company logo. `--name` changes the site identity and home-page title; replace the
fictional product names in the sample prose with your own story as well.

These three templates use hosted sections. Build with a supported container
runtime and serve the output over HTTP with `zel serve` or `zel view`.
They do not enable direct-file viewing or book PDF output. Creation needs no
Docker or Node. No external image service or new runtime dependency is added.
Buttons lead to working sample pages; connect your own signup, purchase or
contact service when you customize the site. No analytics are enabled.

The default styles, alternate light/dark palettes, narrow layouts and no-JavaScript
fallbacks are covered by hosted browser acceptance. The five published starter
archives retain their original bytes and versions.

## Create and edit

```sh
zel create my-docs -t product-docs
zel create my-book -t book-classic --name "The long way home" --set author="A. Writer"
zel new site my-product --template product-studio
```

`zel create` is the short form of `zel new site`. Both use the same implementation.
Without a destination they create `docs/zellij`; without a template they select
`product-docs`. Existing `init`, `new portable`, `new docs` and `new app` retain
their previous behavior.

```text
my-book/
  zel.yaml
  content/
    preface.md
    chapters/
    notes.md
    assets/wave.png
  .zel-template.json
```

Edit the Markdown/YAML, then run `zel build my-book` to create `my-book/site/`.
The parent folder can have any name. Portable output works when you double-click
`site/index.html`. Hosted output requires an HTTP server; hosted builds use the
matching container engine. Creating a template itself needs no Docker or Node.

The destination must be new or completely empty, including hidden files. There
is no overwrite option. Run from its parent when creating into an existing empty
folder; the CLI refuses to replace its current working directory.

`--name` sets the declared `title` variable. Repeat `--set key=value` for other
variables shown by `zel templates show`. Unknown/duplicate variables are errors.
The receipt records the template version and original file checksums; it never
prevents edits or automatically overwrites a manuscript.

## Versions and local templates

```sh
zel create my-book -t book-classic@0.2.0 --offline
zel create my-docs -t ./my-custom-template --offline
```

A local template has `template.yaml` and `files/`, including
`files/zel.yaml` and `files/content/`. Start by copying one of the catalog
sources in the Zellij repository. See the
[template format](https://github.com/mylife-inc/Zellij/blob/main/templates/README.md)
for capabilities, safe text placeholders, asset licenses and limits.

Creation checks paths, compatibility, substitutions and declared assets before
publishing the staged folder. Portable content is checked strictly. Templates
declaring `print: lualatex` also pass the native PDF compatibility check without
typesetting; an unsupported print declaration leaves the destination untouched. Hosted
creation checks YAML syntax; run `zel check --deep --strict` for full hosted
schema and route validation. Template hooks are never executed.

## Release catalogs and offline use

The default catalog is bundled in the executable, so it needs no connection.
Each release that includes this feature also attaches `templates-catalog.json`
and checksummed template archives to the public release mirror. Select that
release's catalog URL explicitly:

```sh
zel create my-docs -t product-docs --catalog <release-catalog-HTTPS-URL>
zel create another-copy -t product-docs --catalog <same-catalog-URL> --offline
```

The second command reuses verified cached files with no network access. Both the
catalog and selected archive must have been cached first. `--cache-dir <folder>`
overrides the normal OS cache directory. `id@version` pins exactly; an unpinned ID
selects the highest version in the chosen catalog. Unsupported versions fail
without creating a site. Old release URLs can disappear under pre-1.0 retention;
bundled, local and already cached copies continue to work.
