---
title: zel serve
description: Preview an existing static export over local HTTP, without rebuilding it.
---

<Callout type="tip" title="Available in source">
`zel serve` runs a native HTTP server. It needs no Docker, Node, or external
server. Native release packages may lag current source; check your binary's help.
</Callout>

```bash title="terminal"
zel serve ./docs-site
zel serve ./dist --port 8080
zel serve ./dist --port 0               # choose a free port
zel serve ./dist --base-path /products/docs
```

The server binds to **127.0.0.1** and prints its actual URL. Open that URL in a
browser. Press **Ctrl-C** to stop the server; the exported files remain on disk.
`serve` does not open a browser automatically. Use [`zel view`](/cli/view) to
build Markdown, serve it, and open the browser together.

## What is served

The supplied directory must contain a regular `index.html`. Both portable
Markdown output and hosted Zellij static exports can be served. Files are read
as built, with MIME types for HTML, CSS, scripts, images, fonts, and downloads.
GET and HEAD are supported; other HTTP methods return 405. Responses disable
caching so reloading sees files replaced by another build.

| Request | File or response |
| --- | --- |
| `/` | `index.html` |
| `/guide/setup.html` | The exact file |
| `/guide/setup` | `guide/setup.html`, if present |
| `/guide/` | `guide/index.html`, if present |
| `/guide` when it is a directory with an index | Redirect to `/guide/`, preserving its query |
| Missing file | `404.html` with status 404, or a plain 404 response |

The server does not list directories or fall back to the home page for unknown
routes. It rejects traversal, malformed URL encodings, hidden metadata paths,
and symlinks/junctions inside the export. `.well-known` remains available.
The supplied root itself may be an explicitly chosen filesystem alias; it is
resolved before serving. HTTP requests cannot select a different root.

## Deployment prefixes

If a hosted export uses a `basePath` such as `/products/docs`, mount it at that
same prefix:

```bash title="terminal"
zel serve ./dist --base-path /products/docs --port 8080
# Serving at http://127.0.0.1:8080/products/docs/
```

This controls the server mount. It does not rewrite HTML, change `site.yaml`, or
change the prefix the site was built for. Paths outside the mount return 404.
For ordinary portable output, leave the prefix at `/` unless you want to test
a subdirectory deployment.

## Build, serve, view, and dev

- [`zel build`](/cli/build) creates an output directory and exits. Portable output
  also works by double-clicking `index.html` without any server.
- `zel serve` previews an existing output directory over HTTP. It does not
  watch the Markdown source or rebuild pages.
- [`zel view`](/cli/view) builds portable Markdown once, serves it, and opens a
  browser. Add `--watch` to rebuild Markdown and reload that preview on edits.
- [`zel dev`](/cli/dev) runs the existing hosted YAML/MDX development workflow
  through the container engine.

This loopback server is for local preview. It does not provide public hosting,
TLS, authentication, or image optimization. Use a static host or
[`zel image run`](/cli/image#zel-image-run) for the corresponding deployment.

## Options

| Option | Meaning | Default |
| --- | --- | --- |
| `[dir]` | Existing static output directory | `dist` |
| `--port <n>` | Local port; `0` chooses an available one | `3000` |
| `--base-path <path>` | Absolute URL mount prefix | `/` |

An occupied port produces an error; the server does not silently switch ports.
Use `--port 0` when the particular port does not matter. Serving does not modify
the export or require an ownership marker. Build's separate output-ownership
rules still apply when producing or replacing an export.
