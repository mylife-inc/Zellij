---
title: features
description: Select optional portable capabilities or editable-wrapper rendering and dependencies.
---

```bash
zel features all
zel features maths
zel features diagrams --site-root docs/manual
zel features maths,diagrams --site-root my-wrapper
zel features none
```

The selection replaces the previous selection. Use `all` or `none` alone.
The current directory's editable wrapper is selected first; otherwise normal
site discovery uses `./zel.yaml`, then `./docs/zellij/zel.yaml`. `--site-root`
selects a custom portable site or wrapper explicitly. The command runs natively
without Docker, Node, package installation or network access.

| Selection | Portable site | Editable Next.js wrapper |
| --- | --- | --- |
| `maths` | `markdown.math: true`, Mermaid off | Enable math; require remark-math and rehype-mathjax |
| `diagrams` | `markdown.mermaid: true`, math off | Enable Mermaid; require mermaid |
| `maths,diagrams` or `all` | Both enabled | Enable both; require all three packages |
| `none` | Both disabled | Disable both; remove their direct requirements |

## Portable sites

The command edits `zel.yaml`, preserving comments and unrelated settings.
Run [`zel build`](/cli/build) afterward to apply the selection. The portable
renderer uses its existing offline math and Mermaid implementations; no packages
are downloaded. Anchors/aliases inside the `markdown` settings must be expanded
before this command can safely edit them.

## Editable wrappers

Select a wrapper created by [`new app`](/cli/new) or [`eject`](/cli/eject), with
`zellij.config.yaml` and a compatible built local engine dependency. The command
updates `package.json` with explicit `zellij.features` rendering selection,
feature package requirements and the engine's required security overrides. Other manifest fields, unrelated dependencies and lockfiles remain.
If a feature package is also declared in another dependency category, the command
asks you to reconcile those declarations first.

Run `npm install` when enabling features, then rebuild the app or restart its
development server. A selected feature with missing packages fails the Next
configuration step with installation guidance.

`none` disables hosted math and Mermaid rendering even if their packages are
still installed. Formulas stay as source text and Mermaid fences stay as code;
native `mindmap` fences continue rendering. The engine declares these libraries
as optional peers, so a fresh wrapper with neither selected does not install them.
Npm may retain packages needed by other dependencies or an existing installation;
the CLI does not delete node_modules or rewrite lockfiles.

New wrappers save an explicit selection, defaulting to none. Older wrappers
without `zellij.features` retain automatic detection of installed packages until
`zel features` is run. Use a current engine with feature-selection support;
older engines are refused before the manifest is changed. Both Turbopack and
Webpack builds honor the selection.

A hosted content folder by itself has no npm manifest. Select its editable
wrapper, or use a suitable engine image variant for container builds. The command
does not write an ignored feature setting into hosted `zel.yaml`.

Invalid selections, unsupported layouts and `--json` exit `2` before modification.
Writes are staged and refuse detected concurrent edits. Available in current
source; public `zellij-v0.1.3` predates it.
