---
title: zel fmt
description: Format site YAML locally while preserving its values and comments.
---

<Callout type="tip" title="Available in source">
Formatting runs natively without Node, Docker or network access. The public
`zellij-v0.1.3` binary predates this implementation.
</Callout>

```bash title="terminal"
zel fmt                         # format the discovered site
zel fmt --check                 # report differences without writing
zel fmt docs/manual             # a custom site folder
zel fmt ./existing-content      # an explicit legacy content folder
```

## Files selected

With no directory argument, `fmt` selects `./zel.yaml`, then
`./docs/zellij/zel.yaml`. A custom folder is explicit; there is no parent or
recursive site discovery. See [configuration](/cli/config#site-layout-and-discovery).

For a configured hosted site, it formats `zel.yaml` and `.yaml`/`.yml` files
under `content/`. For a portable site, it formats only `zel.yaml`: YAML files
inside portable content are downloadable attachments, not site configuration.
An explicit raw hosted folder formats its YAML recursively.

Markdown, MDX, media, hidden paths, `node_modules`, hosted `assets/` directories,
the selected build output and directories marked as Zellij exports are skipped.
Formatting does not read the whole software repository or change `docs/specs/`
outside the selected site. Selected symbolic links and Windows junctions are
rejected rather than followed.

## Formatting rules

| Area | Behavior |
| --- | --- |
| Section fields | Known section types put `type` first, required fields next, optional fields in schema order, then unknown fields in their original order. |
| Comments and anchors | Retained. Section reordering is skipped when comments, anchors, aliases, tags or multiline scalars need their original context. |
| Indentation | Two spaces for structural indentation. |
| Quoting | Single-line strings use plain syntax when it preserves their type and works in flow collections; otherwise quotes remain. Multiline quoted spelling is retained. |
| Short collections | Nested scalar maps and scalar lists become inline collections when they fit within 80 columns. |
| Long collections | Wrapped as needed; existing flow collections can retain braces or brackets. |
| Literal and folded text | Values, significant trailing spaces and blank lines are preserved. |
| Line endings | LF, with a final newline except where multiline scalar semantics require the authored ending. |

For example:

```yaml
cta:
  - label: "Get started"
    href: "/guide"
    style: "primary"
```

becomes:

```yaml
cta: [{ label: Get started, href: /guide, style: primary }]
```

This command formats syntax; it does not validate section schemas or repair
broken references. Use [`zel check`](/cli/check) for those checks.

## Check mode and writes

```yaml
      - run: zel fmt --check
```

`--check` prints each file that would change and exits **1** when differences
exist, **0** when formatting is already clean. It creates no temporary files and
changes nothing. Invalid configuration, malformed/unsupported single-document
YAML, unsafe paths, or a transformation that would change parsed values fail
with exit **2**. I/O failures use exit **1**.

Normal formatting parses every selected file and compares its values before
writing anything. It stages replacements beside the files, preserves file
permissions, then checks for concurrent changes before replacing each file
atomically. A late syntax error leaves all source files unchanged. This is not
a transaction across files if storage fails during the final replacements.

Format once and review the diff before adding `--check` to CI. There is no
`--force` option and no JSON output mode.

## Options

| Option | Meaning | Default |
| --- | --- | --- |
| `[dir]` | Site root or explicit legacy content folder | Configured-site discovery |
| `--check` | Report changes without writing; exit 1 when changes are needed | Off |
