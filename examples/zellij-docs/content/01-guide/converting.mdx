---
title: Converting existing docs
description: Bring a MkDocs or Docusaurus tree across, and know what does not come with it.
---

```bash
zel detect ./docs
zel convert ./docs --out ./content
zel check ./content
```

The output goes in a **new folder**. The original is never touched, so a
conversion you dislike costs nothing but the folder you delete.

The current CLI source supports `zel cv ./docs --out ./manual --layout site
--validate` to convert and check in one step. Hosted validation needs a running
container runtime; ordinary conversion does not. Referenced local assets are
copied by default. `--assets skip` omits them and retains their original URLs for
manual repair, while document links still convert. Both controls are newer than
the published rc.1 CLI; see [conversion options](/cli/convert).

## What is recognised

| Format | Read from | |
| --- | --- | --- |
| MkDocs | `mkdocs.yml` | The `nav` tree, `site_name`, `site_description`, `docs_dir`. |
| Docusaurus | `sidebars.js`, `.ts`, `.cjs` or `.json` | Categories, doc entries, links and nesting — when declarative. |

`zel detect` says which, and how sure it is. A folder with the format's own
config file is certain; one that merely looks like the default layout is not,
and an ambiguous tree asks rather than guessing. Guessing between two plausible
formats produces a conversion that is wrong in ways nobody notices for a month.

Authored YAML page titles and descriptions are preserved. Sidebar labels stay
separate from page titles, and other front matter remains in comments for review.
Docusaurus custom document IDs resolve to their real source files, using the
default number-prefix rules and per-document `parse_number_prefixes` setting.
`sidebar_label` is preserved; draft and unlisted documents are excluded and
reported. An explicit empty sidebar stays empty. Autogenerated blocks preserve
nested folders and sort by document/category positions and numeric prefixes;
other sidebar entries keep their array order. Category labels come from
`_category_.json`, `.yml` or `.yaml`, with index-document and folder fallbacks.
Index documents remain accessible as the first child link, or a single link
when they are the folder's only page. Partial and hidden documents are excluded.
Malformed metadata, ambiguous IDs and missing targets fail before writing output.

Manual category links import their linked documents. Generated category indexes
become editable MDX pages with titles, descriptions and nested child links under
`01-guide/category/`; generated filenames avoid authored routes. Empty or fully
excluded categories do not produce empty pages. Explicit document and generated
category slugs become route overrides under `/guide`, keeping original file
locations and relative asset bases. Navigation, search and converted file links
use the new routes. Documents without a slug retain filename-derived routes.
Duplicate or unsafe routes fail before writes. Source styling, generated-index
images/keywords, original deployment prefixes, root-relative source URLs and
plugin routing still need review. See [the conversion reference](/cli/convert) for
metadata precedence, compatibility rules, heading anchors and link handling.
These metadata improvements are newer than the published rc.1 executable.

## What does not come across

**A marketing landing page.** Every one of these tools describes a documentation tree.
Zellij has that *and* marketing pages built from 23 section types with no
equivalent in the source. So a conversion writes a faithful guide folder, a
`site.yaml` carrying whatever identity it could find, and a `pages.yaml` with
one hero to build on — and says so in the report, every time.

**Links out of the sidebar.** A sidebar holds pages; an external link belongs in
`menu.yaml`. They are reported rather than dropped.

**Pages the navigation never mentioned.** A page hidden from its own navigation
may have been hidden deliberately, so it is listed rather than silently
published.

```
2 thing(s) could not be carried over:
  https://blog.acme.dev: "Blog" is an external link; sidebars hold pages. Add it to menu.yaml.
  draft.md: on disk but absent from the navigation; not converted
```

## When Docusaurus computes its sidebar

`sidebars.js` is a JavaScript module, not a data file. Most are data wearing
JavaScript's clothes and read fine. Some are not:

```js
module.exports = require('./generated').map((item) => ({ ...item }));
```

That is not read at all. The converter falls back to the folder and names the
construct that stopped it:

> `sidebars.js` contains a require() call, so it was not read. The converter does
> not execute JavaScript; navigation came from the folder in alphabetical order.
> Review and reorder `_sidebar.yaml`.

JavaScript-looking text inside strings or comments remains data; an ordinary
label containing an ellipsis does not trigger the folder fallback.

Declining is the point. A sidebar half-read from a file the converter did not
understand would look finished and be wrong.

## Markdown that is not MDX

Zellij compiles guide pages as MDX, which is Markdown plus JSX. That addition is
not free: `{` opens an expression and `<` opens a tag. Prose written for MkDocs
has never had to care, so `set {timeout} to <n> seconds` is good Markdown and a
syntax error here.

The converter escapes both where they would be read as code, and leaves fenced
blocks and inline spans alone — a backslash inside a command someone is going to
copy and run is worse than the problem it solves.

| In the source | Becomes | |
| --- | --- | --- |
| `{timeout}` | `\{timeout\}` | In prose only. |
| `a < b` | `a &lt; b` | Unless it opens a real tag. |
| `<https://x.com>` | `[https://x.com](https://x.com)` | MDX has no autolinks. |
| ` ```sh {x} < y ``` ` | unchanged | Code is quoted by definition. |

<Callout type="warning" title="check does not compile MDX">
`zel check` validates the content model — links, section types, sidebar
entries. It does not compile your Markdown. A converted folder can pass `check`
and still fail to build, so build it once before you throw the original away.
</Callout>

## When nothing is recognised

A folder of plain Markdown with no configuration has no structure to convert
from — no order, no grouping, no titles beyond the first heading. Rather than
invent one, the command says so and points at the other route:

```bash
zel context zellij.md
```

That writes the whole content model as one file. Give it to an AI agent with
your Markdown and ask for a content folder; the agent has the structure it needs
and you have `zel check` to hold it to account.
