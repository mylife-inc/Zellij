title: Quickstart
description: A running Zellij site in three files and one folder.
---

This builds a real site from scratch. It takes about ten minutes, and nothing
in it is throwaway — the wrapper app you write here is the one you keep.

<Steps>

<Step title="Install">

```bash title="terminal"
npm install @shebka/zellij next@16.2.x react@19.2.x react-dom@19.2.x
```

Node 20.11 or newer.

</Step>

<Step title="Write the wrapper app">

Three files, and none of them change as your site grows.

<CodeGroup>

```tsx title="src/app/layout.tsx"
import '@shebka/zellij/styles.css';
import { createZellijRootLayout } from '@shebka/zellij';

export default createZellijRootLayout();
```

```tsx title="src/app/[[...slug]]/page.tsx"
import { createZellijPages } from '@shebka/zellij';

const zellij = createZellijPages();

export const generateStaticParams = zellij.generateStaticParams;
export const generateMetadata = zellij.generateMetadata;
export default zellij.Page;
```

```js title="next.config.js"
export default {
  transpilePackages: ['@shebka/zellij'],
};
```

</CodeGroup>

<Callout type="warning" title="Page is returned by name, not as default">
Destructuring a key called `default` does not produce a module default export,
which the App Router requires. Re-export it as above.
</Callout>

</Step>

<Step title="Add the build steps">

```json title="package.json"
{
  "scripts": {
    "predev": "zellij prepare",
    "dev": "next dev",
    "prebuild": "zellij prepare",
    "build": "next build"
  }
}
```

`zellij prepare` copies your content assets into `public/` and writes the
search index. Both are build-time steps; nothing happens at request time.

</Step>

<Step title="Write some content">

```yaml title="content/site.yaml"
name: Acme
tagline: The operations platform your team already knows how to use
theme: cupertino
nav:
  search: true
  themeSwitcher: true
```

```yaml title="content/pages.yaml"
- name: home
  title: Acme — operations that run themselves
  description: One system for workflows, approvals and reporting.
  layout: landing
  sections:
    - hero
    - features
```

```yaml title="content/sections/hero.yaml"
type: hero
headline: Operations that run themselves
subhead: One system for workflows, approvals and reporting.
cta:
  - { label: Get started, href: /guide, style: primary }
```

```yaml title="content/sections/features.yaml"
type: feature-grid
heading: Everything in one place
columns: 3
items:
  - { icon: workflow, title: Workflows, body: Branches and conditions, no scripting. }
  - { icon: check-check, title: Approvals, body: Sign-off with a full trail. }
  - { icon: bar-chart, title: Reporting, body: Ask in plain language. }
```

</Step>

<Step title="Run it">

```bash title="terminal"
npm run dev
```

That is a working site. Before you go further, try:

```bash title="terminal"
npx zellij check
```

which loads the folder and reports everything wrong with it without building
anything.

</Step>

</Steps>

## Add documentation

Make a folder — call it whatever you like — and put a `_sidebar.yaml` in it.

```yaml title="content/guide/_sidebar.yaml"
- label: Getting started
  items:
    - installation
    - configuration
```

```mdx title="content/guide/installation.mdx"
# Installation

Everything you need to get running.
```

That folder is now a documentation tree at `/guide`, with a sidebar,
breadcrumbs, an on-this-page rail, prev/next links, and its pages in the ⌘K
search index. It also becomes eligible for the top navigation bar.
