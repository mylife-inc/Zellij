Zellij's engine is a private package. The base image is not — so a site can be
built and published by anyone, with no access to the source.

```bash
docker build -f site.Dockerfile --build-arg CONTENT=docs -t my-docs .
docker run --rm -p 3000:3000 my-docs
```

## What the base image is

`ghcr.io/mylife-inc/zellij-base` is a Next.js wrapper with the engine at
`/opt/zellij` and **nothing installed**. It carries a manifest describing what a
site will need, and `npm install` happens when a site is built.

That is deliberate. The image people pull is a quarter of a gigabyte rather
than a whole one, and the dependencies were being fetched at build time either
way — a site build resolves its own lockfile regardless. The cost moved; it did
not appear.

The wrapper inside it is generated by the same scaffold `zel new app` uses, so
the image cannot drift from what you would get locally.

## Building a site from it

Copy this into your own repository. It needs nothing from Zellij's source:

```dockerfile title="site.Dockerfile"
ARG ZELLIJ_IMAGE=ghcr.io/mylife-inc/zellij-base
ARG ZELLIJ_VERSION=latest
ARG CONTENT=content
ARG FEATURES=

FROM ${ZELLIJ_IMAGE}:${ZELLIJ_VERSION} AS build
ARG CONTENT
ARG FEATURES

RUN rm -rf /app/content
COPY ${CONTENT}/ /app/content/

RUN if [ -n "$FEATURES" ]; then node /opt/zellij/bin/zellij.mjs features "$FEATURES" /app; fi
RUN npm install --install-links
RUN npx zellij check content
RUN npm run build

FROM node:24-alpine AS runtime
# ... copy .next/standalone, .next/static and public
```

Two things worth noticing.

`zellij check` runs **before** the build, so a broken link fails the image
rather than shipping a site with a dead page in it.

The runtime stage copies only the compiled output, so neither the engine nor
`node_modules` reaches what you deploy. The engine is genuinely absent from the
image you ship — not merely unused in it.

## Optional features

Mathematics costs about fifty megabytes to install and diagrams about a
hundred, and most documentation wants neither. Both are optional: a site that
does not ask for them never fetches them, and the engine renders without them
rather than failing.

Two ways to the same place:

```bash
# Pick an image that has them
FROM ghcr.io/mylife-inc/zellij-base:-all

# Or ask for them when building
docker build --build-arg FEATURES=maths,diagrams ...
```

| Feature | Turns on | Costs |
| --- | --- | --- |
| `maths` | `$…$` and `$$…$$` | ~50 MB at build time, nothing at runtime |
| `diagrams` | ```mermaid fences | ~100 MB at build time, ~10 MB in the browser |
| `all` | both | |

<Callout type="info" title="Mindmaps need neither">
A `mindmap` fence is laid out during the build by the engine itself, so it works
in every variant and adds nothing to any of them. Maths is also build-time only
— MathJax typesets to SVG and never reaches the browser. Only Mermaid ships
anything to a reader.
</Callout>

Published variants: `:latest` (neither), `:-maths`, `:-diagrams`, `:-all`.
Because nothing is installed in the base image they are all the same size — the
saving lands on whoever builds a site, not on whoever pulls the image.

## Getting the wrapper app out

You do not need to clone anything to have the app on disk:

```bash
docker create --name tmp ghcr.io/mylife-inc/zellij-base:latest
docker cp tmp:/app ./my-site
docker rm tmp
```

That gives you the wrapper with the engine already installed. `zel eject` does
the same thing in one command.

## In a pipeline

A repository with its source and a `docs/` folder beside it needs no access to
Zellij:

```yaml title=".github/workflows/docs.yml"
name: Documentation

on:
  push:
    branches: [main]

jobs:
  publish:
    runs-on: ubuntu-latest
    permissions:
      contents: read
      packages: write

    steps:
      - uses: actions/checkout@v4

      - uses: docker/login-action@v3
        with:
          registry: ghcr.io
          username: ${{ github.actor }}
          password: ${{ secrets.GITHUB_TOKEN }}

      - name: Build and push
        run: |
          docker build \
            -f site.Dockerfile \
            --build-arg CONTENT=docs \
            --build-arg FEATURES=maths \
            -t ghcr.io/${{ github.repository }}/docs:${{ github.sha }} \
            -t ghcr.io/${{ github.repository }}/docs:latest .
          docker push --all-tags ghcr.io/${{ github.repository }}/docs
```

The only credential is the token GitHub already gives the job. Nothing here
needs a licence, an account, or the engine's source.
