Set one word:

```yaml title="site.yaml"
theme: cupertino
```

The theme picker in the bar above changes it live. That is the fastest way to
understand what a theme actually does here — every page on this site restyles,
including this one.

## The fourteen

| Name | What it is |
| --- | --- |
| `midnight` | Dark, electric accent, tight geometry — a product-tool aesthetic. |
| `paper` | Light, warm, editorial serif headings over a cream page. |
| `terracotta` | Warm Moroccan palette with generous curves — the Shebka house style. |
| `mono` | Austere black and white with a single hot accent and brutalist edges. |

| `forest` | Deep greens, natural and calm. |

| `carbon` | Near-black developer-tool aesthetic with monospace-flavoured headings. |

## What a theme controls

A theme is a token set, emitted as CSS custom properties. No component contains
a colour, a font, a radius or a duration.

<Tabs>
<Tab label="Palette">

Per colour mode: `bg`, `fg`, `muted`, `surface`, `border`, `accent`,
`accent-fg`, `inverted-bg`, `inverted-fg`.

```css
--zellij-bg: #ffffff;
--zellij-accent: #0071e3;
--zellij-inverted-bg: #1d1d1f;
```

</Tab>
<Tab label="Geometry and type">

```css
--zellij-radius / --zellij-radius-button / --zellij-radius-media
--zellij-container / --zellij-section-gap / --zellij-nav-height
--zellij-font-heading / --zellij-font-body / --zellij-font-mono
--zellij-tracking / --zellij-heading-weight / --zellij-display-scale
```

`display-scale` is what makes `cupertino` headlines enormous and `porcelain`
headlines quiet, without either theme touching a component.

</Tab>
<Tab label="Shadow and motion">

```css
--zellij-shadow-card / --zellij-shadow-float
--zellij-motion-duration / --zellij-motion-ease
--zellij-motion-distance / --zellij-motion-stagger
```

</Tab>
</Tabs>

## Light and dark

```yaml title="site.yaml"
mode: system     # light | dark | system
```

Every theme defines both palettes. `system` follows the operating system and
can still be overridden by the visitor with `nav.themeToggle: true`; the choice
is remembered.

The mode toggle and theme picker work independently. Saved modes are restored
only when `nav.themeToggle` is enabled; saved theme names are restored only when
`nav.themeSwitcher` is enabled and the theme is available on the site. Enabled
preferences are applied as the page loads. Disabled controls keep the configured
`mode` or `theme`, even if another site on the same origin saved a different
choice. Unavailable storage leaves the configured defaults usable, and controls
still work for the current page.

Code blocks follow the mode too — Shiki emits both palettes at build time and a
CSS variable picks between them, so switching is instant and no highlighter
runs in the browser.

## Overrides

Tweak a theme without forking it:

```yaml title="site.yaml"
overrides:
  accent: "#E86A33"
  accentForeground: "#ffffff"
  radius: lg              # none | sm | md | lg | xl
  fontHeading: "Georgia, serif"
  fontBody: "system-ui, sans-serif"
```

Values are validated before they reach the stylesheet. They come from a config
file rather than a request, but they are interpolated into CSS, so they are
checked rather than trusted.

## The runtime picker

```yaml title="site.yaml"
nav:
  themeSwitcher: true
```

<Callout type="info" title="Opt-in, because it changes what ships">
Normally Zellij emits the site's theme tokens, plus a page's own tokens when it
declares an override. A runtime switcher needs every theme present in the page,
so each swatch can paint itself and switching does not require a download.
</Callout>

## Per-page themes

A sections page may override the theme of its content:

```yaml title="pages.yaml"
- name: launch
  theme: aurora
  sections: [launch/hero]
```

The override applies below the navigation bar, inside that page's main content.
The header, footer, and guide pages retain the site theme. It includes the page's
palette, fonts, geometry and theme-specific presentation, works without
JavaScript, and follows the site's light/dark mode, including system changes.
Site token `overrides` still apply. Anchor offsets continue to use the actual
shared header's height.

The runtime picker changes the site theme; it does not replace an explicitly
authored page theme or save that page theme as a visitor preference. Navigating
to a page without an override uses the selected site theme again.

Use page overrides sparingly to keep the site's visual identity consistent.

## Adding a theme

Themes live in the engine, not in content. A new one is a token set added to
`THEMES` and a name added to `THEME_NAMES` — no component changes, and a test
asserts every theme emits every token and clears the contrast floor.
