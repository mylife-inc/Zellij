title: The menu
description: Declaring the top bar, and what happens when you don't.
---

`menu.yaml` declares the items in the top bar and nothing else. Search, the
theme picker, the light/dark toggle, the CTA and the announcement bar are
configured under `nav:` in `site.yaml` — they are chrome, not navigation.

```yaml title="menu.yaml"
- { name: Features, page: features }
- { name: Security, url: /features#security }

- name: Solutions
  items:
    - { name: For startups, page: solutions/startups }
    - { name: For enterprise, page: solutions/enterprise }

- name: Resources
  items:
    - name: Learn
      items:
        - { name: Guide, page: guide, description: Install and operate., icon: book }
        - { name: Blog, url: "https://blog.example.com" }
    - name: Company
      items:
        - { name: About, page: about, icon: users }
```

## One target per item

Each item declares **exactly one** of these:

| Key | Target |
| --- | --- |
| `page:` | A sections page or guide folder, by name. Validated at build time. |
| `url:` | Any literal href — external, or internal when it needs an anchor. Not validated. |
| `items:` | Children, which makes this a drawer. |

A `page:` that names nothing fails the build, listing what exists:

```
Broken menu references (1):
  · menu › Docs: "Docs" → page: guides
    No page or guide folder is named "guides".
    Available: about, features, guide, pricing, solutions/startups
```

`url:` is never validated, because the engine has no way to check it. Use
`page:` wherever you can — it is the only form that survives a rename.

## Drawers and panels

In rc.12, every desktop drawer opens as a
viewport-wide band directly below the top bar. Plain leaf items form a responsive
grid. A child with its own `items` creates a headed column, as in the `Resources`
example above. Existing `menu.yaml` files need no migration. Long panels scroll
within the available viewport height, including when an announcement wraps.

Panels slide down on hover or activation, with keyboard entry via ArrowDown,
Escape dismissal and reduced-motion support. Mobile keeps the section drawer
and Back navigation described below.

Optional per item: `description` and `icon` (a [lucide](https://lucide.dev)
name, kebab-case; an unknown one fails the build), and `wide: true` to force
the grouped panel form.

<Callout type="info" title="Leaving the site is visible">
An item whose `url:` is external gets an outbound icon and opens in a new tab,
so the visitor keeps their place. `newTab: false` overrides that.
</Callout>

## When there is no menu.yaml

One is derived — the **union** of everything reachable:

1. every entry in `pages.yaml`, in file order
2. every guide folder not already named above

The union matters. Deriving from `pages.yaml` alone would leave guide folders
with no way in, and a site that quietly hides half of itself is worse than one
with an untidy bar.

Past `menuOverflowAfter` items — seven by default, set it in `site.yaml` — the
remainder collapses into one trailing drawer. A book with thirty chapters gets
a usable bar with no configuration at all.

The desktop header measures the space available after reserving its edge controls.
When labels do not fit, trailing items move into **More**; they return to the
bar when more space becomes available. Dropdowns keep their destinations, and
grouped menus keep their headings, descriptions and external-link behavior.
This also responds to larger text, font and theme changes. `menuOverflowAfter`
remains an upper limit, rather than a promise that every item will always fit.

The bar spans the viewport with consistent edge padding. In rc.11, `nav.align`
defaults to `center`: the product logo/home link and menu form one group centered
on the viewport. An optional `brand.company` logo sits at the far left, while
search, theme controls and other utilities stay at the far right. Unequal logo
and control widths do not shift the centered group. Explicit `nav.align: left`
remains available. Search opens the search dialog. On mobile, the product home
link remains beside the company mark and the navigation drawer contains the
complete menu. The optional GitHub destination moves into that drawer on
mobile, leaving room for both company and product identity.

### Mobile section views

In rc.11, the hamburger opens a full-screen menu on phones and a side drawer on
larger mobile/tablet layouts. Primary section names use large touch targets.
A section with children opens its own view with a title and its links; grouped
menus retain their headings, descriptions and icons within that view.

The top-left **Back** arrow returns to the main menu and restores its scroll
position and focused section. The top-right **Close** button exits the entire
menu; Escape does the same. A direct page link navigates immediately and closes
the menu. External links preserve their configured `newTab` behavior. Reopening
always starts at the main menu. The visible backdrop on tablets also closes it.

Transitions respect reduced motion and `motion: none`. The existing `menu.yaml`
is the source for both desktop and mobile navigation; no separate menu or new
configuration is needed. The optional GitHub link and CTA buttons stay in the
main menu's footer. Long lists scroll independently of the Back/Close controls.

When resizing switches between mobile and desktop navigation, open menus close
and keyboard focus moves to a visible navigation control. Focus already in the
page content stays there. Rapid changes use the final viewport width, even if
a navigation control briefly disappears and returns. Choosing another control
or clicking page content takes precedence over that restoration.

CLI rc.21 and its renderer apply the same rule when desktop links
move into or out of **More**: delayed restoration respects a newer focus or
pointer choice instead of pulling focus back to the menu. During rapid desktop
resizes, restoration waits for the matching menu layout to appear, so an older
queued callback cannot discard the latest focus destination.

Header updates, such as changing from transparent to
solid while scrolling, preserve the focused link inside an open drawer.

<Callout type="warning" title="Declaring a menu turns derivation off">
When `menu.yaml` exists it is the whole bar. Nothing is appended, so a folder
you forgot to list will not appear. That is deliberate: a declared menu is a
decision, and the engine should not second-guess it.
</Callout>

## Sites that share an owner

`brand.logo.href` is how a family of sites belongs to one company. Point it at
the hub and the mark leaves for the hub, while `brand.title` becomes the way
home within this site.

```yaml title="site.yaml"
brand:
  logo:
    src: assets/shebka.svg
    alt: Shebka
    href: https://shebka.com
  title: PayOS
```

Omit `href` and the logo links to `/`, which is the single-site case; `title`
is then unnecessary.

This needs no session state and no query parameters, and it works for someone
who arrived from a search result rather than from the hub — which is most
people.

For separate company and product icons, use `brand.company` for the owner and
keep `brand.logo` for the product. The company mark appears first, at the far
left of the bar. Its `newTab` boolean defaults to `false`; set it to `true` to
open the company website in a separate tab. The product logo's default
destination remains the documentation home. See the
[complete branding example](/guide/site-config#brand). The earlier single-logo
configuration above remains supported; the additional company slot is newer
than `v0.2.0-rc.4`.
