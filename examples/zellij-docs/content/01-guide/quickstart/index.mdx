Four hands-on labs. Each starts where you are, ends with a site somebody else
can read, and says what every command does before you run it.

First, the one thing they all need.

## Install `zel`

`zel` is the Zellij CLI — a single native binary. It needs no Node, no npm, and
no clone of anything.

```bash title="terminal"
curl -fsSL https://raw.githubusercontent.com/mylife-inc/releases/main/zellij/install.sh | sh
```

<Callout type="info" title="What that script does">
Detects your platform, finds the latest release, downloads the archive built
for it, **verifies it against its published SHA-256**, and puts one binary in
`~/.local/bin`. It writes nothing else and needs no privileges.

Read it first if you would rather — it is about a hundred lines of POSIX
shell, and it lives beside the binaries it installs:
[install.sh](https://github.com/mylife-inc/releases/blob/main/zellij/install.sh).
</Callout>

Pin a version, or install somewhere else:

```bash title="terminal"
ZEL_VERSION=v0.1.0 ZEL_INSTALL_DIR=/usr/local/bin \
  curl -fsSL https://raw.githubusercontent.com/mylife-inc/releases/main/zellij/install.sh | sh
```

On Windows, or anywhere piping to a shell is not allowed: download the archive
from [the releases page](https://github.com/mylife-inc/releases/releases?q=zellij),
verify it against its `.sha256`, and put `zel` on your PATH.

### Check it

```bash title="terminal"
zel --version
zel doctor
```

`doctor` reports what is installed and what is missing.

```
Container runtime
  ✓ docker     27.4.0 via unix:///Users/you/.colima/default/docker.sock
  ✓ engine     ghcr.io/mylife-inc/zellij-base:0.1.0
```

Two of the four labs need that runtime line, because building a site means
running the engine — a Next.js application that `zel` runs in a container so
you never install Node. Any of Docker, Podman or Colima will do; on a Mac,
`brew install colima && colima start` is the smallest of the three.

Writing, converting and validating content need no runtime at all.

### Which one is yours

| If… | Go to |
| --- | --- |
| There is no documentation yet, and no repository to put it in | [Lab 1](/guide/quickstart/from-scratch) |
| There is documentation, in some other tool or none | [Lab 2](/guide/quickstart/existing-docs) |
| You are starting a codebase and want the docs to ship with it | [Lab 3](/guide/quickstart/new-project) |
| The codebase exists and the docs need to catch up | [Lab 4](/guide/quickstart/existing-repo) |

Labs 1 and 2 are about **writing**, and end with a published site. Labs 3 and 4
are about **shipping from a repository**, and assume you have content already —
from one of the first two, or the sample the scaffold writes.

that use one that is still landing, and gives the way round it. [The command
reference](/cli) has the current state of each.
</Callout>
