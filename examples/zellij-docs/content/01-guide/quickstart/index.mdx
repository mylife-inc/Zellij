Choose the result you want: a typeset book, a rich website from a template,
a new documentation folder, or documentation shipped alongside product code.
Each walkthrough explains the source files, commands and generated outputs.

## Before you start

Local websites, previews and cached PDF generation need only `zel`. The first
rich/PDF build downloads verified tools; later builds can reuse them offline.
Install the CLI below, then [pick your use case](#pick-your-lab).

| Workflow | Additional requirement |
| --- | --- |
| Create a template or build a portable reading website | None |
| Rich website, validation or preview | Internet for the first renderer download |
| Cached PDF | Internet for the first compiler/private runtime download |
| Native deployment | An existing provider destination and credentials |
| Hosted Next `dev` | Internet for the first development, renderer/private runtime and source downloads |
| Image packaging, explicit container development/PDF | A running supported Linux container runtime |

Downloads go under `$ZELLIJ_HOME`, defaulting to `~/Dev/config/zellij` on macOS
and Linux, or `Dev/config/zellij` under your Windows user profile. Homebrew
and Scoop manage the executable themselves; downloaded resources still use this
home. See [resource directories](/cli/config#zellij-home).

<Callout type="info" title="Short workflows">
The book and template walkthroughs use `bp`, `bs`, `vw` and `lint`.
Cached PDF and Next development use verified downloads by default. Install rc.25 below, check `zel --version`, then
follow the use case that matches your project. See [all shortcuts](/cli/shortcuts).
</Callout>

## Install `zel`

`zel` is the Zellij CLI: a single native binary, with no runtime of its own.
Use published [candidate 0.2.0-rc.25](https://github.com/mylife-inc/Zellij/releases/tag/v0.2.0-rc.25)
for this guide. Stable `0.1.3` predates these workflows. The candidate's six native
packages and both Linux image architectures passed
[release acceptance](https://github.com/mylife-inc/Zellij/actions/runs/45791545516).

If you already use a package manager, choose one of these installation methods:

```bash title="Homebrew — macOS and Linux"
brew install mylife-inc/tap/zel
```

```powershell title="Scoop — Windows"
scoop bucket add mylife-inc https://github.com/mylife-inc/scoop-bucket
scoop install mylife-inc/zel
```

Update managed installations with `brew upgrade mylife-inc/tap/zel` or
`scoop update; scoop update zel`. The standalone archive installers below are
another option. Use one installation method to avoid competing copies on PATH.

<Tabs>
<Tab title="macOS and Linux">

```bash title="terminal"
curl -fsSL https://github.com/mylife-inc/Zellij/releases/download/v0.2.0-rc.25/install.sh -o install.sh
ZEL_VERSION=v0.2.0-rc.25 ZEL_RELEASE_BASE_URL=https://github.com/mylife-inc/Zellij/releases/download/v0.2.0-rc.25 sh ./install.sh
```

Works on **Apple Silicon and Intel Macs**, and on Linux **x86-64 and arm64** —
the script reads `uname` and fetches the matching build. This candidate also
includes native Windows x64 and ARM64 archives.

To select another installation directory, reuse the downloaded installer:

```bash title="terminal"
ZEL_VERSION=v0.2.0-rc.25 \
ZEL_RELEASE_BASE_URL=https://github.com/mylife-inc/Zellij/releases/download/v0.2.0-rc.25 \
ZEL_INSTALL_DIR="$HOME/.local/bin" sh ./install.sh
```

It installs to `$ZELLIJ_HOME/bin`, defaulting to `~/Dev/config/zellij/bin`,
and prints PATH guidance. `ZEL_INSTALL_DIR` takes precedence. For the default
resource home, add this line to your shell profile and open a new terminal:

```bash
export PATH="${ZELLIJ_HOME:-$HOME/Dev/config/zellij}/bin:$PATH"
```

The installer does not edit shell profiles. Homebrew keeps its own executable
location. Renderer and remote-template downloads share the
[Zellij resource home](/cli/config#zellij-home).

</Tab>
<Tab title="Windows">

Candidate 0.2.0-rc.25 supports native Windows x64 and ARM64. In PowerShell:

```powershell
Invoke-WebRequest https://github.com/mylife-inc/Zellij/releases/download/v0.2.0-rc.25/install.ps1 -OutFile install.ps1
.\install.ps1 -Version v0.2.0-rc.25 -ReleaseBaseUrl https://github.com/mylife-inc/Zellij/releases/download/v0.2.0-rc.25
```

`-InstallDir` selects a directory and takes precedence over `ZELLIJ_HOME`.
The default is `$env:ZELLIJ_HOME\bin`, falling back to
`%USERPROFILE%\Dev\config\zellij\bin`. Add the resolved directory to your
user PATH and open a new terminal. The installer checks the archive checksum and
binary version before replacing a prior installation.

Native rich websites, portable books and cached PDF need no WSL or Docker. Inside WSL, use the Linux
installation instructions instead. Hosted container workflows have separate
runtime requirements.

</Tab>
</Tabs>

<Callout type="info" title="What that script does">
Detects your platform, downloads the explicitly selected candidate archive,
**verifies it against its published SHA-256**, and installs one executable in the
selected directory. It preserves the existing executable if validation fails and
does not edit your PATH. The default user locations need no administrator rights.

You can read the attached
[install.sh](https://github.com/mylife-inc/Zellij/releases/download/v0.2.0-rc.25/install.sh)
or [install.ps1](https://github.com/mylife-inc/Zellij/releases/download/v0.2.0-rc.25/install.ps1)
before running it.
</Callout>

## Check it

```bash title="terminal"
zel --version
zel doctor
```

`zel --version` should report `zel 0.2.0-rc.25`. For a rich site, `zel doctor`
reports the standalone renderer's cache path and readiness without downloading
it. Neither a rich file build nor a portable web-only build needs a successful
Docker check. Container-based operations have separate requirements; see
[`zel doctor`](/cli/doctor) for setup and endpoint diagnostics.

## Pick your lab

### Write a book and generate PDF

Create a classic, technical or study edition; edit its manuscript; generate
`pdf/book.pdf` or a complete reading website with a PDF download. Follow
[the book walkthrough](/guide/quickstart/books) for chapter order, equations,
print settings, offline builds and sharing.

```sh
zel create my-book -t book-technical
cd my-book
zel pdf
zel bp
```

Both PDF commands use the verified cached compiler by default. PDF-only export
writes `pdf/`; the combined build writes `site/`.

### Create a beautiful website from a template

Choose a product launch, software platform, creative studio or API starter.
[The template walkthrough](/guide/quickstart/website-templates) explains each
editable file, branding, guide pages, live preview and both file/HTTP outputs.

```sh
zel create my-website -t product-launch
cd my-website
zel b
```

Double-click `site/index.html`. No HTTP server is needed. For editing with
automatic refresh, use `zel vw` (also `zel view --watch`).

## One optional tool, for publishing

`zel netlify`, `zel cf`, `zel vc`, `zel ghp` and `zel s3` build and deploy
static sites directly. They need the selected provider's destination and
credentials, not a separately installed provider CLI. Start with
[deployment setup](/cli/deploy); review draft previews where supported and
use `--prod` explicitly for production.

`zel ci` generates a local workflow from saved site settings. It does not
publish your repository or upload credentials unless you explicitly request
provisioning. See the repository labs and [CI reference](/cli/ci).

### Installing a container runtime

Only image operations and explicitly selected container development/PDF need this. Follow [container setup](/guide/containers), then run `zel doctor`
for your chosen site/backend. Creating and previewing the sites above does not
require this step.

### Start the image downloading now

If you are choosing a container workflow, `zel pull` acquires the matching engine
image ahead of time. It is optional; ordinary rich builds download their renderer
to the resource home instead. See [image selection](/cli/pull).
