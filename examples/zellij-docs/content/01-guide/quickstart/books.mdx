---
title: Write a book and generate a PDF
description: Choose a book edition, edit the manuscript, and generate a reading website and typeset PDF with zel alone.
---

**You will create:** an editable manuscript, a website that opens by double-click,
and an optional LuaLaTeX PDF with a title page, contents and chapter numbering.
Only `zel` is needed; no separate Docker, Node.js, Python or LaTeX installation.

<Callout type="info" title="Short commands in rc.21 source">
The short recipes below use the upcoming rc.21 CLI: `zel pdf` selects the cached
compiler by default, and `zel bp` builds the website and PDF together. If
`zel --version` reports published rc.20, replace `zel pdf` with
`zel pdf --pdf-backend cached`, `zel bp` with
`zel build --pdf --pdf-backend cached`, `zel lint` with
`zel check --deep --strict`, and `zel vw` with `zel view --watch`.
The [installation page](/guide/quickstart#install-zel) identifies the published version.
</Callout>

## 1. Choose a book edition

```sh
zel templates
zel templates show book-technical
```

| Template | A useful starting point for | Included examples |
| --- | --- | --- |
| `book-classic` | Essays, narrative nonfiction or a novel | Cover, preface, part, chapters and appendix |
| `book-technical` | Mathematics, science or programming | Equations, proofs, code, citations, glossary and index |
| `book-study` | A study guide or reflective book | Passages, commentary, questions, footnotes and reference catalogs |

The templates contain original sample text. Choose one, then replace its content
and artwork. Their coordinated web and print designs share typography and color
choices; print pagination is designed for paper rather than copying the screen.

## 2. Create your manuscript

Run these commands from the directory where you want the new book folder:

```sh
zel create my-book -t book-technical --name "Reasoning clearly" --set "author=A. Writer"
cd my-book
zel lint
zel b
```

The same commands work in macOS/Linux shells and Windows PowerShell. Replace
`book-technical` with either other book ID if preferred. The destination must be
new or empty; creation never overwrites an existing manuscript.

```text
my-book/
  zel.yaml
  README.md
  .zel-template.json
  content/
    preface.md
    chapters/01-first.md
    chapters/02-second.md
    notes.md
    references.json
    glossary.json
    index.json
  site/                    generated by zel b
```

Double-click `site/index.html` now. It is a complete portable reading edition
with navigation and theme controls. The book templates use this reading layout;
choose a [website template](/guide/quickstart/website-templates) for large product
sections, animated headings and landing pages.

## 3. Edit the book and add a chapter

Edit Markdown under `content/`. In `zel.yaml`, change `book.title`,
`book.subtitle`, `book.authors` and the reading order. Technical and study
templates include JSON catalogs for citations, glossary entries and the index;
replace their fictional sample entries with your own sources and terms.

To add a third chapter, create `content/chapters/03-practice.md`:

```markdown
# Put the idea to work

Explain the next idea here. Use ordinary Markdown headings, lists and links.

## A worked example

An inline formula such as $a^2 + b^2 = c^2$ belongs with its explanation.
```

Add its entry beside the existing chapter entries in `zel.yaml`:

```yaml
book:
  # Keep the existing version, title, authors and other settings.
  chapters:
    - id: foundations
      title: From pattern to proof
      chapters:
        - {id: first, source: chapters/01-first.md}
        - {id: second, source: chapters/02-second.md}
        - {id: practice, source: chapters/03-practice.md}
```

This is an excerpt to merge into the existing `book` block, not a replacement
configuration. Paths are relative to `content/`. Each discovered Markdown file
must appear in the reading order; keep unpublished drafts outside `content/`.
Zellij generates the title page, contents, numbering and previous/next links.
The [book reference](/cli/books) explains numbered equations, theorem/proof
blocks, citations, glossary and index syntax.

## 4. Preview while writing

```sh
zel vw
```

This builds, starts a local HTTP server, opens the browser and rebuilds after
edits. Press Ctrl-C to stop. `zel vw --no-pdf` keeps previews fast if you later
enable PDF in the configuration. For a simple saved output, `zel b` is enough;
double-click viewing never needs this preview server.

## 5. Generate only the PDF

```sh
zel pdf --check
zel pdf
```

`--check` validates print compatibility without downloading or typesetting.
`zel pdf` writes **`pdf/book.pdf`**, alongside generated TeX and build records,
and leaves the website unchanged. Open the PDF in your usual viewer and check
page breaks, artwork, equations and references.

The first PDF build downloads the verified compiler and private runtime into
`$ZELLIJ_HOME`, defaulting to `~/Dev/config/zellij` (under your user profile on
Windows). Subsequent builds reuse them. To require an entirely cached build:

```sh
zel pdf --offline
```

Missing cached resources produce an actionable error; Zellij does not silently
start a container. An explicit `--pdf-backend container` remains available for
users who want the separate container compiler.

## 6. Generate the website with a PDF download

```sh
zel bp
```

This is `zel build --pdf`. It writes **`site/index.html`** and
**`site/_zellij/pdf/book.pdf`**, adding a working download link to the reading
pages. It generates both from the same manuscript snapshot. Share the whole
`site/` folder to preserve navigation and assets, or distribute just the PDF.
`zel bp --offline` uses already cached tools without downloads.

To include PDF in every ordinary build, edit the existing top-level `pdf` block:

```yaml
pdf:
  enabled: true
  paper: a5
  font-size: 11
```

Then `zel b` alone produces both outputs. `zel b --no-pdf` produces only the
website for that invocation. Choose `a4` or `letter` for another paper size;
supported font sizes are 10, 11 and 12 points. Use the
[print-style settings](/cli/books#custom-print-styling) for chapter openings,
colors and named fonts. Web theme switching does not regenerate the PDF.

## 7. Publish or hand over the result

For offline readers, zip the entire `site/` directory. They can unzip it and
double-click `index.html`, including its PDF download link. For future authors,
also supply `zel.yaml`, `content/`, the README and installation instructions.
Generated `site/` and `pdf/` are replaceable outputs; edit the manuscript instead.

For an existing Netlify project with credentials configured, `zel netlify`
builds and uploads a draft; `zel netlify --prod` publishes after review. See
[deployment setup](/cli/deploy). PDF is included in delivery when
`pdf.enabled: true`. Other destinations and generated CI are also supported.

Print currently supports English, French, German and Spanish LTR, plus Arabic
RTL, with the documented font set. Arbitrary raw TeX packages, custom system
fonts and every possible Markdown extension are not supported. Check the
[print boundaries](/cli/books#first-print-template-and-current-boundaries) before
moving a complex manuscript, and inspect an actual PDF before distributing it.
