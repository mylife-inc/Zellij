<Callout type="info" title="Included in candidate 0.2.0-rc.10">
`compose` requires a matching CLI and engine at rc.6 or later. This section is
for the hosted engine; portable Markdown output does not render the hosted
section catalog.
</Callout>

`compose` gives you layout and content building blocks without writing React or
CSS. The existing sections remain shorter choices for common designs. Start with:

```bash
zel new section compose --out content/sections/intro.yaml
# Short alias:
zel ns compose --out content/sections/intro.yaml
```

<Callout type="info" title="Next candidate: source 0.2.0-rc.11">
Video, caption tracks, transcripts, container-aware layouts, layers, semantic
content nodes and configurable scroll stages below are new in source rc.11. They need a matching rc.11 CLI
and engine build; the published rc.10 candidate does not include them yet.
</Callout>

Replace the generated content with a composition and reference `intro` in
`pages.yaml`, just like any other section:

```yaml
type: compose
version: 1
label: Introduction
id: introduction
layout: {kind: stack, align: center, gap: large}
children:
  - type: heading
    text: Make room for a beautiful idea.
    level: 1
    scale: display
    gradient:
      colors: ["#ad4e2e", "#b9832d"]
      effect: reveal
  - type: text
    text: "A clear structure, **thoughtful details**, and room to breathe."
    size: lead
  - type: button
    label: Read the guide
    href: /guide
```

`label` names the section in a page's side rail; it is not an extra visible
heading. `id`, `background`, `padding`, `motion` and `titleGradient` retain their
shared meanings. `titleGradient` supplies a fallback gradient for headings;
a heading's own `gradient.colors` takes precedence. A composition containing a
level-1 heading supplies the page heading. Otherwise the page retains its usual
accessible fallback heading.

## Layout and groups

A root or group accepts `layout` with `kind: stack`, `grid`, `split` or `layers` (source rc.11). Omitted
layout means a stack. All preserve source reading order and collapse to a single
column below 760 pixels. In source rc.11 that threshold measures the space
available to each layout, not the whole browser window: a grid inside a narrow
card stays stacked even on a desktop. Print always uses one column. Browsers
without container-query support retain the readable single-column layout.

| Field | Values | Default |
| --- | --- | --- |
| `gap` | `none`, `small`, `medium`, `large` | `medium` |
| `align` | `start`, `center`, `end`, `stretch` | `start` |
| `columns` (grid only) | 2–4 | 3 |
| `ratio` (split only) | `equal`, `wide-start`, `wide-end` | `equal` |

Alignment controls text alignment and cross-axis alignment within cells; it does
not reorder the children. A split creates two columns on wider screens; put one
group in each column when it should contain several elements.

```yaml
- type: group
  layout: {kind: grid, columns: 2, gap: medium, align: stretch}
  children:
    - type: group
      surface: tinted
      padding: medium
      radius: large
      children:
        - {type: heading, text: A clear starting point, level: 3, scale: subtitle}
        - {type: text, text: Explain the first idea here.}
    - type: group
      surface: tinted
      padding: medium
      radius: large
      children:
        - {type: heading, text: Room to grow, level: 3, scale: subtitle}
        - {type: text, text: Explain the second idea here.}
```

Groups accept `surface: plain | tinted | inverted | accent`,
`padding: none | small | medium | large`, and `radius: none | medium | large`.
Their defaults are `plain`, `none`, and `none`. Colours follow the active theme.

## Layers and placement (source rc.11)

A layered layout puts foreground content over an image or a silent video backdrop.
Use `place` on its direct children. It accepts `top-start`, `top-center`, `top-end`,
`center-start`, `center`, `center-end`, `bottom-start`, `bottom-center`, or
`bottom-end`. Each child needs a distinct position; omitted `place` means `center`.
Put a group in a position when several elements belong together. `place` outside
a layered layout is an error. Positions use logical start/end, including RTL.

```yaml
type: compose
version: 1
label: A layered introduction
layout:
  kind: layers
  backdrop: {kind: image, src: assets/landscape.webp, alt: ""}
  tone: dark
  scrim: 0.7
  height: medium
children:
  - type: group
    place: center-start
    children:
      - {type: heading, text: Give the idea a place.}
      - {type: text, text: A few clear words against a quiet background.}
  - {type: button, place: bottom-end, label: Read more, href: /guide}
```

`tone: dark` (default) uses white foreground text and a black scrim; `light` uses
dark text and a white scrim. `scrim` is 0–1, default 0.65; choose sufficient
contrast for your image. `height: compact | medium | tall` sets a desktop minimum
of 24/32/42rem, not a fixed height that clips copy. Desktop placements occupy
separate cells in a three-by-three grid; they do not overlap one another.

Below 760px of available container width, the image sits above the copy and
children follow source order. Print does the same. This is deliberate: visual
placement does not change the authored reading or keyboard order. Text stays
readable without JavaScript. Nested groups retain their own surface colors.

A video backdrop uses `kind: video`, `src`, required `poster` and required `label`.
Use an actual video-file URL or local asset, not a YouTube/Vimeo page. It is muted
and loops only after the reader presses **Play background**; a persistent control
pauses it. Reduced-motion changes and printing pause playback. Without JavaScript,
the poster remains. Keep meaningful speech/video content in a normal `video`
element with captions and a transcript. Backdrops are decorative.

## Elements

| Type | Content and options |
| --- | --- |
| `heading` | Required `text`; `level` 1–4 (default 2); `scale: display | title | subtitle` (default title); `weight: regular | semibold | bold` (default bold). |
| `text` | Required `text`, supporting the same inline Markdown as FAQ answers; `size: small | body | lead` and `tone: normal | muted`. Defaults: body, normal. Block Markdown/MDX is not supported here. |
| `image` | Required `image` asset path and meaningful `alt`; optional inline-Markdown `caption`; `ratio: landscape | square | portrait` (default landscape). |
| `button` | Required `label` and `href`; `style: primary | secondary | ghost` (default primary). External links use the existing new-tab behavior. |
| `stat` | Required string `value` and `label`. Quote numeric YAML values. |
| `divider` | A separator; no extra fields. |
| `media-accordion` | Required `label` and 2–8 `items`; the same synchronized text/image component as [the concise section](/sections/media-accordion). Supports `mediaSide`, `ratio`, `fit` and `itemHeadingLevel`. |
| `video` (source rc.11) | Required `label` and `src`; optional `poster`, inline-Markdown `caption`, WebVTT `tracks`, and `transcript` link. Uses the same player as `video-embed`. |
| `prose` (rc.11) | Required `body`: plain block Markdown, including paragraphs, lists, tables and code. No MDX execution or raw HTML. |
| `list` (rc.11) | Required 1–24 inline-Markdown `items`; `ordered` defaults to false. |
| `quote` (rc.11) | Required inline-Markdown `text` and plain-text `author`; renders a blockquote and attribution. |
| `icon` (rc.11) | Required Lucide `name` and accessible `label`; `size: small | medium | large` gives 24/40/64px. |
| `code` (rc.11) | Required `title` and literal `code`; optional `language` class. Selectable code, with no execution or automatic syntax highlighting. |
| `table` (rc.11) | Required `caption`, `rowLabel`, 1–8 unique `columns`, and 1–40 `rows` with `label` and one inline-Markdown `cells` value per column. |
| `disclosure` (rc.11) | Required plain `summary` and inline-Markdown `body`; `open` defaults to false. Native keyboard-operable details. |
| `carousel` (rc.11) | Required `label` and 2–12 `items`; each has `title` and optional inline-Markdown `body`, `image`, `alt`, `href`. |
| `gallery` (rc.11) | Required `label` and 1–12 `items` with `image`, meaningful `alt`, optional plain `caption`; `columns` is 2–4, default 3. |
| `group` | Required `children`; optional layout, surface and rc.11 `scroll` settings. |

Elements other than dividers also accept `effect: reveal`, which uses the site's
existing entrance motion. Omit it for an ordinary element. The site's `motion:
none` and the reader's reduced-motion preference take precedence.

## Semantic and interactive content (source rc.11)

Use semantic nodes instead of arranging ordinary text to imitate a table, list or
code block. For example:

```yaml
- type: table
  caption: Publication formats
  rowLabel: Format
  columns: [Screen, Print]
  rows:
    - {label: Text, cells: [Readable, Readable]}
    - {label: Video, cells: [Playback, Source and transcript]}
- type: disclosure
  summary: Does this need JavaScript?
  body: "This disclosure works without it. [Read the guide](/guide)."
- type: code
  title: Build the site
  language: sh
  code: zel build
```

Tables retain their headers and captions, and scroll horizontally when needed.
Carousels use the existing scroll-snap component: touch/trackpad scrolling works
without JavaScript; buttons enhance it. Keyboard or reduced-motion scrolling is
instant. Galleries reuse the existing lightbox with arrow-key navigation, Escape
to close and focus restoration. Without JavaScript, each thumbnail links to its
original image. Modified clicks retain normal browser behavior. A gallery's
`label` names its dialog so multiple galleries remain distinguishable.

Print expands disclosures, lays out every carousel card and prints gallery
thumbnails/captions. `prose` supports ordinary Markdown; raw HTML/JSX markup is
dropped and expressions are never evaluated. H1 syntax becomes H2 so a prose
block cannot take ownership of the page heading. Prose headings have no automatic
anchor IDs; use heading nodes and section IDs for the surrounding structure.
Use `markdown-prose` as a separate section when you need the engine's MDX components.

## Video inside a composition

Add a video wherever a text or image element can go, including inside a group.
This example places copy beside a video; replace the asset paths with your own
files and `/guide/transcript` with a real page:

```yaml
type: compose
version: 1
label: Product demonstration
layout: {kind: split, gap: large, align: center}
children:
  - type: group
    children:
      - {type: heading, text: See the idea in motion.}
      - {type: text, text: A short demonstration, ready when you are.}
  - type: video
    label: Product demonstration
    src: assets/demo.mp4
    poster: assets/demo-poster.webp
    caption: "A **two-minute** tour."
    tracks:
      - src: assets/demo.en.vtt
        srclang: en
        label: English captions
        kind: captions
    transcript: /guide/transcript
```

`label` names the play button and player for assistive technology. A visible
caption describes the video; it does not replace synchronized captions for
speech or sound. Supply WebVTT files in `tracks` and a readable transcript when
the recording needs them. Each track requires `src`, a language tag such as
`en` or `pt-BR` in `srclang`, and a human-readable `label`. `kind` is `captions`
(default) or `subtitles`; up to eight tracks are supported. These tracks apply
to self-hosted videos. YouTube/Vimeo captions are managed by those providers.
Remote media with caption tracks must allow anonymous cross-origin requests;
local files in `content/assets` avoid that hosting requirement.

The player has a fixed 16:9 frame and never starts by scrolling into view.
With JavaScript, a play action loads the video and moves keyboard focus to it.
Without JavaScript, self-hosted video has native controls with `preload="none"`;
provider videos retain a direct source link. No third-party iframe loads before
play. The source and transcript links remain available in print, where playback
controls are hidden. A 16:9 frame contains portrait footage without cropping.

## Gradient reveal

A heading may use `gradient: {colors: [accent, fg], effect: reveal}`. Supply two
or three colours: palette tokens `fg`, `muted`, `accent`, `accent-fg`,
`inverted-fg`, or a quoted 3-, 6-, or 8-digit hexadecimal colour. Choose colours
with sufficient contrast against the surrounding surface.

The gradient blends over solid text as the heading becomes visible, between
15% and 65% visibility. It reverses when the heading leaves view. Omit the effect
(or use `effect: none`) for a static gradient. The text stays readable without
JavaScript or an intersection observer; reduced motion shows the finished
heading. Forced colours and print use solid text. Print preserves authored
reading order and does not reproduce animation.

## Scroll stages (source rc.11)

A root or group can declare `scroll`. Set the enclosing section's `motion` to
`expressive`; `none`, `subtle` and the reader's reduced-motion preference keep
ordinary layout. Stages cannot nest.

```yaml
type: compose
version: 1
label: A story in motion
motion: expressive
scroll:
  pin: true
  distance: 1
  start: 0.2
  end: 0.8
  from: {y: 32, scale: 0.94, opacity: 0.6}
  to: {y: 0, scale: 1, opacity: 1}
children:
  - {type: heading, text: A quiet arrival.}
  - {type: text, text: Scroll to let the idea settle into place.}
```

`pin` defaults to true. `distance` reserves 0.25–2 extra viewport heights (default
1) while pinning. With `pin: false`, the stage stays in normal flow and progress
measures its passage through the viewport. `start` (0–0.95, default 0) and `end`
(0.05–1, default 1) select the active part of that progress; start must be less
than end. Values before/after the range hold the corresponding endpoint, and
scrolling back reverses the effect.

Both `from` and `to` are required objects. Their optional fields are `y` in pixels
(-80–80, default 0), `scale` (0.85–1.15, default 1) and `opacity` (0.5–1, default 1).
Only transforms and opacity animate. Focused content is restored to full opacity
and its ordinary position.

Stages activate only when both the viewport and available container are at least
760px wide and the content fits below the navigation bar. Long content, resizing,
reduced motion, forced colors, print, missing observer APIs and no-JavaScript
output retain ordinary readable content without extra scroll space. These are
bounded single stages, not a multi-scene timeline or a video scrubbing system.

## Authoring and checking

Use complete JSON values to choose node/layout variants, then refine scalar
fields. This avoids changing a node type while leaving incompatible fields:

```bash
zel ns compose --set label=Overview \
  --set-json 'children=[{"type":"group","children":[{"type":"heading","text":"Hello","level":1}]}]' \
  --set children.0.children.0.text="Hello, world" \
  --out content/sections/overview.yaml
zel explain compose
zel check --deep --strict
```

A root or group contains 1–24 children. Up to three groups may nest along a path,
with at most 128 elements and one level-1 heading in each composition. Both
native authoring and engine checking enforce these bounds. Deep checks follow
nested image/video/poster/track paths, button/transcript links and inline Markdown; unknown fields warn and
fail strict checks.

## Named presets

```bash
zel presets                              # descriptions
zel list presets --json                  # names, types and descriptions
zel ns -p product-hero --out content/sections/intro.yaml
zel ns compose --preset split-story --out content/sections/story.yaml
```

The bundled presets are `product-hero`, `split-story`, `feature-cards` and
`media-accordion`. Each expands into an ordinary composition with editable
content and layout. No preset reference remains in the generated file. They
work offline and accept the same `--set`, `--set-json`, `--count`, `--unset`
and `--interactive` editing options as other sections. Use `--out` when inferring
the type with `-p`; an output positional argument requires the explicit type.
Image paths are placeholders to replace before building. These section presets
are distinct from the whole-site templates offered by `zel templates`.

## How universal is it?

`compose` is an extensible composition system, not a promise that every possible
website section can be expressed. It can create many heroes, split stories,
feature grids, calls to action and mixed-media sections using the same validated
tree. A large title that changes from solid text to a gradient as it enters view
is already supported by `gradient.effect: reveal`.

| Capability | Status |
| --- | --- |
| Nested stacks, grids and splits; styled groups; headings, text, images, buttons, statistics and separators | Available in rc.10 |
| Solid-to-gradient heading reveal; entrance reveal; readable reduced-motion, no-JS and print fallbacks | Available in rc.10 |
| Synchronized media accordion and four editable section presets | Available in rc.10 |
| Video nodes, WebVTT captions, transcript links and layouts responsive to their containing space | Implemented in source rc.11; not yet published |
| Image/video backdrops and nine distinct foreground placements | Implemented in source rc.11; not yet published |
| Single sticky/unpinned stages, authored ranges and bounded transforms | Implemented in source rc.11; not yet published |
| Multi-scene scroll stories, video scrubbing and arbitrary timelines | Not implemented |
| Block Markdown, icons, lists, quotes, code, tables, disclosures, carousels and galleries | Implemented in source rc.11; not yet published |
| MDX execution and arbitrary existing sections as children | Not implemented |
| Independent media selectors and feature explorers | Not implemented |

Use a dedicated section when it already provides the behavior you need, such as
`media-panel` for copy over background media, `card-carousel` for a carousel,
`pricing-table` for pricing, or `faq` for questions. Those sections can sit next
to compositions. The composer reuses the video, media-accordion, carousel-track and lightbox components through its own node schemas; it does not embed arbitrary section definitions. Arbitrary
author-supplied JavaScript and unrestricted CSS are outside its declarative
contract. Book pagination and PDF composition remain part of the book system.
