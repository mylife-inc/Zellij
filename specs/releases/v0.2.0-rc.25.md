## Candidate highlights

- Keyboard focus remains in the visible desktop navigation when rapid resizing
  moves links into or out of **More**. An older pending restoration no longer
  discards the focus destination for a menu that has not appeared yet. A newer
  keyboard or pointer choice still takes precedence.
- The correction is included in the shared renderer used by rich double-click
  websites, HTTP exports and the standard Next.js wrapper. Rebuild existing
  websites with this candidate to receive it.
- Global `--json` help now includes the already supported `templates` command.
  No command syntax or configuration migration is required.

The existing cached build, validation, preview, development and optional PDF
workflows remain available. Downloads stay under `ZELLIJ_HOME`, defaulting to
`~/Dev/config/zellij`. Template versions and previously published archive bytes
are unchanged.

## Verification and limits

The source focus regression fails before the correction and passes afterward
in both Chromium and WebKit. The original natural resize sequence and the full
browser suite also pass without retries. Packaged and public-download acceptance
are separate release gates; these notes alone do not establish their outcome.

The historical WebKit rendering stall and documentation hydration timeout remain
unresolved. Deferred live-provider and external catalog checks are not claimed
complete. This remains a release candidate, with no stable 1.0 or zero-bug claim.
