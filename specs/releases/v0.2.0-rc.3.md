# Zellij CLI 0.2.0-rc.3

This candidate packages the complete documented CLI command surface and the
fixes merged since rc.2. It ships native x64 and ARM64 packages for GNU/Linux,
macOS and Windows, plus matching engine images for both Linux architectures.
The user authorized this release before the remaining live deployment-provider
and external-runner verification. Those checks remain separate follow-up work.

## Changes since rc.2

- **Jekyll imports:** read declarative TOML configuration as well as YAML;
  support collection `sort_by` after scoped defaults; respect explicit order
  lists while reporting stale entries. Typed metadata and exact integer
  ordering are preserved within the documented subset.
- **Sphinx imports:** convert contained parsed `include` fragments; support
  wildcard and reversed toctrees, source inclusion/exclusion patterns and
  independent include-resource discovery. Exclusions take precedence, explicit
  navigation must select eligible documents, and unsupported executable
  configuration is rejected before output is written.
- **Cloudflare Pages:** accept success-only upload acknowledgements and provide
  a fallback 404 document when the export has none, so unknown URLs do not
  silently return the home page.
- **Railway:** inspect the staged environment patch without decrypting variable
  values, and wait for deployment startup before requiring running instances
  at `SUCCESS`.
- **Vercel:** accept empty successful upload acknowledgements as well as JSON
  objects. Project and deployment responses still require valid identity and
  status data.
- **Local previews:** cancel polling when a page is hidden or navigated away
  from and resume cleanly when restored, preventing stale responses from
  triggering a reload.
- **Documentation:** reconcile the command reference and quickstarts with the
  `zel.yaml` / `content/` / `site/` layout, current commands, short aliases,
  editable wrappers and precise importer/deployment limits. Installation and
  engine-image examples select rc.3 explicitly.

## Implemented CLI surface

- Create portable or hosted sites, editable Next.js apps, projects, pages,
  guides and all 23 section types, with interactive and scriptable authoring.
- Inspect schemas, formats and targets; generate AI context and completions;
  diagnose configuration and runtime prerequisites.
- Check, format, watch, build, serve, view and develop sites. Portable Markdown
  builds need no Docker or Node and support direct `file://` navigation, search
  and bundled assets. Hosted Next.js output requires HTTP.
- Import MkDocs, Docusaurus, VitePress, Jekyll, Hugo and Sphinx within their
  documented declarative subsets; copy, skip or link assets to a public base URL.
- Build static-site and Next.js images, run/push them, and publish both Linux
  architectures under one image manifest using configured builders or CI.
- Deploy through Netlify, Cloudflare Pages, Vercel, GitHub Pages, S3, existing
  Fly web apps and Railway image services; compose conversion and delivery with
  `ship` and saved settings with `publish`.
- Generate GitHub Actions, GitLab and CircleCI pipelines. Remote workflow
  dispatch and optional credential provisioning remain GitHub-specific.
- Pull engine images, verify/self-upgrade the executable, extract editable
  wrappers, and select optional rendering features.

## Verification and limits

The normal release gates cover unit/protocol tests, native packages/installers,
real container builds and browser behavior. The release workflow verifies all
six public native downloads and all four engine variants on native AMD64/ARM64
after publication. Consult the linked workflow results for the final outcome;
the presence of a release page alone does not prove every image job passed.

Live Netlify fixture, Cloudflare Pages, GitHub Pages and Railway checks passed
at earlier recorded revisions. Fly/S3 and actual GitLab/CircleCI runner checks
are deferred until after this release; Vercel live testing remains user-deferred.
Protocol tests do not replace these live checks or establish zero undiscovered
bugs. The prepared disposable-test workflows remain available for later use.

Importers do not execute source projects or reproduce arbitrary themes,
plugins, extensions, dynamic configuration or every source-generator feature.
Their accepted syntax and manual migration requirements are documented. Section
authoring creates new content; it is not an editor for arbitrary existing YAML.

The Netlify hosting-comment hydration issue on the full documentation site
remains separate from CLI fixture acceptance. The old production site and
domain remain in place. Candidate publication leaves stable installers,
`latest` image tags and production documentation deployment unchanged.

Use the pinned instructions below, including the matching rc.3 engine image
for hosted/container commands. Existing candidate installations can explicitly
select `zel upgrade v0.2.0-rc.3`; stable `0.1.3` predates this command contract.
