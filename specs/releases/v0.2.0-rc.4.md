# Zellij CLI 0.2.0-rc.4

This development candidate adds independent company branding and Homebrew
distribution support, and fixes the controlled hosting-annotation hydration
failure. It retains the implemented command families and documented importer
boundaries from rc.3. It is not the final 1.0 release.

## Changes

- **Company and product icons:** optional `brand.company` appears before the
  product logo in portable and hosted sites. It has its own HTTP(S) destination
  and `newTab` setting; the product logo still returns home by default. Hosted
  company icons support an independent dark image. Portable-to-hosted conversion
  preserves both marks, including company-only configurations.
- **Hosting annotations:** React-managed styles and the preference bootstrap
  tolerate the reproduced head-newline/comment mutation. Tests still reject
  actual hydration and runtime errors. Live Netlify verification is deferred.
- **Preview upgrades:** `zel upgrade --preview` selects the highest published
  semantic version including candidates. `--preview --check` checks without
  replacing the binary. Stable remains the default channel; explicit versions
  remain supported, and downgrades remain refused.
- **Homebrew:** the release includes `zel.rb`, generated from the same SHA-256
  inventory as the six native packages. The owned `mylife-inc/tap` installs the
  correct Mac/Linux x64/ARM64 binary and Bash/Zsh/Fish completions. See the
  [tap](https://github.com/mylife-inc/homebrew-tap) for the currently published
  formula; recipe generation alone does not mean tap publication succeeded.
- **Package ownership:** a Homebrew installation refuses self-replacement before
  network access and directs the user to `brew upgrade mylife-inc/tap/zel`.
- **Matching engines:** the default engine image is pinned to the CLI's own
  version rather than an older stable `latest` tag. Explicit configuration and
  `ZELLIJ_IMAGE` still override it.
- **Documentation and delivery:** current documentation examples select rc.4.
  Retarget the six saved delivery workflows after publication succeeds, before
  removing their previous artifacts. Earlier live delivery results remain
  evidence for their original revisions; retargeting a workflow is not a new
  live-provider verification result.

## Installation and release boundaries

Use the pinned native instructions below, or the published Homebrew formula.
Homebrew installation is explicitly a preview while its formula selects an rc.
Standalone installers retain explicit version selection; a stable lookup does
not silently substitute a preview if no stable release exists.

Native package and archive verification covers six OS/architecture targets.
Homebrew acceptance additionally exercises four native targets, completions,
package-manager ownership, a portable site build, formula-revision upgrade and
uninstall. Public downloads and engine images require the release workflow's
post-publication checks; consult its final results.

The new template catalog/create command, composable section format, additional
interactive section presets and opt-in LaTeX/PDF books remain planned. This
release does not claim those future features are implemented. Live Fly/S3,
Vercel and external CI runner verification remain deferred. Production docs
migration is separate; the old website/domain remain in place.

Superseded Zellij distributions may be retired under the user's pre-1.0 policy
only after the replacement is accepted and current references have migrated.
Source/audit history and other products in the shared release repository remain
intact. Cutting this tag does not itself establish that retirement is complete.
