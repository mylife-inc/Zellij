## Candidate highlights

This candidate brings the native CLI and installers up to the current Zellij
documentation workflow. It is intended for acceptance testing before 0.2.0 stable.

- **Portable documentation:** `zel init`, `build`/`b`, `serve`/`s`, `view`/`v`
  and `dev` support Markdown sites without Docker. Generated sites support direct
  `file://` navigation, search, links and bundled assets. Math, mindmaps and
  optional Mermaid rendering have offline support.
- **Short commands and conventional folders:** a documentation folder contains
  `zel.yaml`, `content/` and generated `site/`. Omitted paths discover the current
  documentation folder or `docs/zellij`. Global `--cwd`, `--site-root` and
  `--config` controls support other layouts and named configurations.
- **Hosted sites and images:** generate editable Next.js wrappers, build static
  or Next.js images with `zel si` and `zel ni`, and run/push images with `ir` and
  `ip`. Runtime discovery supports Docker, Podman and nerdctl, with useful
  diagnostics when no runtime is available. Commands do not install or start one.
- **Delivery:** `zel netlify`, `publish`/`pub` and `ship` build and deliver using
  saved settings. `zel ci` generates GitHub workflows pinned to a compatible
  release, including this candidate by default; it can also dispatch workflows.
- **Authoring and maintenance:** validation and formatting, validation watch,
  schema explanations and AI context, import/migration, shell completions,
  `doctor`, `version`, `pull`, `upgrade`, wrapper extraction and rendering-feature
  selection are available. Invocation-only feature overrides cover build,
  preview, development, images, delivery and CI generation.
- **Native packages:** x64 and ARM64 archives for GNU/Linux, macOS and Windows.
  Unix and PowerShell installers verify checksums and executable versions,
  preserve existing installations on failure and leave PATH changes to the user.

## Compatibility and current limits

The stable 0.1.3 executable predates these commands and configuration contracts.
Use the pinned candidate installation instructions below and select its matching
engine image for hosted/container commands. Candidate publication does not deploy
the production documentation website or promote stable installation channels.

The Next.js wrapper is served over HTTP; portable static output supports direct
file opening. A site image build currently selects one target platform. The
published engine images provide both Linux AMD64 and ARM64 manifests. Netlify is
the implemented cloud deployment provider; other providers, broader conversion
fidelity and additional advanced build options remain future work. Unsupported
source constructs during migration still require review of the converted site.

## Acceptance

The release workflow builds and tests all six native archives before upload.
After publication, it downloads archives, checksums and installers from the
development release and, when enabled, the shared releases repository. Native
runner checks cover installation, reported version/architecture, replacement and
failure preservation, upgrade, portable build, serve/view and Ctrl-C shutdown.
The four published engine variants are pulled and executed on both native Linux
architectures. Check the **Release** workflow result before relying on a candidate;
a release page can exist while image publication or acceptance is still failing.
