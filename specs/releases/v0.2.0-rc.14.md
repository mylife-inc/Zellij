# Zellij CLI 0.2.0-rc.14

Rich-site authoring now uses the same downloaded renderer as rich file builds.
Install only `zel`, then use:

```sh
zel check --deep --strict
zel watch --deep --strict
zel view --watch
```

The first rich operation downloads the matching renderer into
`$ZELLIJ_HOME/cache/engines`, defaulting to
`~/Dev/config/zellij/cache/engines`. Subsequent operations reuse the verified
cache. Add `--offline` to refuse downloads. No separately installed Docker,
Node.js, npm or Python is required for these commands.

Validation uses the shared engine schemas and deep checker without executing
authored MDX or generating a website. `check --json` reports target `file` for
standalone rich validation. Content errors and strict warnings exit with code 3;
operational failures remain distinct. `watch` keeps validating after bad edits.

Preview publishes complete successful builds, reloads open browsers and keeps
the previous site available when a later edit fails. Ctrl-C cancels the renderer
and cleans its stage. Rich output remains usable by double-clicking `index.html`;
live-reload code is injected into preview responses only.

Use `--target static` on check, watch or view to retain the container/Next path.
Generated delivery workflows explicitly select static or portable checks to
match their deployment engine. Hosted `dev`, image packaging, deployment
exports, hosted import validation and PDF typesetting retain their documented
prerequisites. Portable web-only authoring remains native. This is a pre-1.0
candidate; live provider verification remains separate.
