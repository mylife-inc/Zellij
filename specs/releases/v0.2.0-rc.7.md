# Zellij CLI 0.2.0-rc.7

This candidate adds shared technical-book references and improves navigation,
Windows installation and generated CI. Publication and acceptance status are
recorded separately; this file is the versioned release description.

## Changes since 0.2.0-rc.6

- Labelled equations share chapter/appendix numbers, stable anchors and
  standalone `\eqref` / `\ref` links across portable HTML, Next and PDF.
- Theorem, lemma, proposition, corollary, definition, example, remark and proof
  blocks use shared statement numbers and references in all three outputs.
- Numeric citations and bibliography use a local CSL-JSON catalog, with
  citation locators, DOI/URL links, footnotes and uncited entries.
- Optional glossary and subject-index JSON catalogs provide definitions,
  see-also links, one level of index subentries, web occurrence backlinks and
  deduplicated linked PDF page numbers.
- Authored book home content starts after the PDF contents with its own running
  header. Existing book-classic 0.2.0 and product-template archives are unchanged.
- Keyboard focus survives responsive-header updates, drawer updates and rapid
  breakpoint changes, while respecting later focus and pointer choices.
- Windows package-manager ownership diagnostics include `scoop update zel`.
  The release includes a checksum-pinned `zel.json` manifest; the owned Scoop
  bucket update and its public acceptance are separate publication gates.
- Generated container CI selects/preflights Docker explicitly, including
  configured PDF and static/Next image jobs. Native portable jobs remain native.
- Release publication now requires successful Scoop lifecycle checks; a failed,
  cancelled or skipped check cannot be bypassed by the publication condition.

For the supported book syntax and limits, see the [book guide](https://github.com/mylife-inc/Zellij/blob/v0.2.0-rc.7/examples/zellij-docs/content/02-cli/books.mdx).
Use the matching `0.2.0-rc.7` engine image when building Next output containing
these book references. Portable web builds require no container runtime; PDF
export remains opt-in and requires a supported Linux container runtime.

## Compatibility and current limits

The classic PDF adapter supports English/LTR books. Multilingual/RTL print,
richer technical/study templates, BibTeX and arbitrary citation styles, per-row
equation numbering, rich glossary definitions, automatic indexing and deeper
index hierarchies remain open. PDF-enabled Next images remain unsupported.
Published template versions and archives are immutable; this candidate does
not silently upgrade their content or declare the remaining expansion complete.

Separate intermittent WebKit overflow and documentation-readiness timeouts have
not reproduced in bounded follow-up checks and remain unexplained. The
reproduced header-focus defects are fixed; later passing runs do not establish
that the unrelated timing findings are resolved. Live provider/external-runner
verification and production-domain migration remain deferred. This is a
preview, with no claim that undiscovered bugs are impossible.
