## Candidate highlights

- Cached PDF is now the default: `zel pdf` generates `pdf/book.pdf` without
  separately installed Docker, Node.js, Python or LaTeX. The compiler and private
  runtime download on first use into the Zellij resource home.
- `zel bp` builds the website and PDF together; `zel bs` creates the HTTP static
  export; `zel vw` previews edits; `zel lint` performs deep/strict validation.
  Existing aliases, full commands and global selectors remain compatible.
- Quickstart includes detailed book/PDF and website-template walkthroughs,
  alongside updated creation, conversion and repository labs.
- Updated book template instructions use new immutable versions: classic
  0.3.0, technical 0.2.0 and study 0.2.0.
- Generated GitHub, GitLab and CircleCI PDF workflows pinned to rc.21 or later
  use cached PDF. Older pins preserve their previous container requirements;
  image jobs still require a builder.

## Compatibility and current limits

`zel pdf` remains PDF-only. `zel bp` publishes the matching website and PDF
under `site/`, including its download link. PDF remains optional; saved
`pdf.enabled` and `--no-pdf` retain their meanings. An explicit
`--pdf-backend container` or `ZEL_PDF_BACKEND=container` retains the isolated
container compiler. The command-line option takes precedence over the environment.

The downloaded compiler's complete matching sources and notices remain separate
release assets under the already approved PDF-only distribution scope. The CLI
and website engine keep their existing terms. Cached builds support `--offline`
once the required packages are present. Source packaging and public-download
acceptance are release gates; these notes alone do not certify a publication.

Existing documented print-language, font and authoring boundaries remain.
Image builders and hosted Next development retain their separate prerequisites.
Historical browser timing findings, external provider checks and distribution
catalog review are not claimed resolved by these changes.
