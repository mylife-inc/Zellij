# Zellij CLI 0.2.0-rc.5

This candidate introduces versioned, editable site templates. It keeps the
existing CLI command families, independent company branding and Homebrew support.
Published 2026-11-12 from PR #138 (`a92c2e9`), after all 20 final-head CI and
29 release/public-download jobs passed. See the
[verification record](../evidence/zellij-rc5-release-2026-11-12.json).

- `zel create [dir] -t <template>` is the short form of `zel new site`.
  Omitted arguments select `docs/zellij` and `product-docs`.
- `zel templates` and `zel templates show <id>` describe the catalog,
  capabilities and editable text variables; `--json` supports tooling.
- Three bundled starters work offline: `product-docs` (portable handbook),
  `product-studio` (hosted product page and guide), and `book-classic`
  (portable reading edition). All have template version `0.1.0`.
- Use `id@version` to pin a template, or `-t ./local-template` for a custom
  directory. `--name` and repeatable `--set key=value` customize declared text.
- Each release attaches `templates-catalog.json` and deterministic,
  SHA-256-checked template archives. `--catalog <HTTPS-URL>` selects one;
  `--offline` reuses verified cached catalog/archive bytes. The public release
  mirror remains usable if the development repository is later sealed.
- Creation validates paths, compatibility, variables and declared assets,
  then publishes a staged directory. Existing authored files are never merged
  or overwritten. A `.zel-template.json` receipt records the source and original
  file checksums. No template hook, package installation or engine runs during
  creation. Hosted creation checks YAML syntax; deep hosted validation remains
  `zel check --strict --deep`.

Use a new/empty destination other than the current working directory; run from
its parent when populating an existing empty folder. Portable templates build
natively and support direct-file navigation. The hosted template uses existing
Cupertino sections and requires the matching engine plus HTTP serving.

The book starter is not yet a full publishing system. PDF/LaTeX, indexes,
bibliography, technical/study editions, richer reading controls and the new
composer/interactive section types remain future milestones. Live provider and
external-runner verification and production documentation migration remain
user-deferred. No claim of zero undiscovered bugs is made.
