# Zellij CLI 0.2.0-rc.13

Zellij-managed downloads now share one resource directory. Set `ZELLIJ_HOME`
to an absolute path, or use its default `~/Dev/config/zellij` (under the Windows
user profile on Windows).

- Standalone installers use `ZELLIJ_HOME/bin`.
- Rich renderers use `ZELLIJ_HOME/cache/engines`.
- Remote template catalogs and archives use `ZELLIJ_HOME/cache/templates`.

Homebrew and Scoop keep their normal executable locations and ownership. Their
installed CLI uses the same resource directory. Explicit `ZEL_INSTALL_DIR`,
`-InstallDir`, `ZEL_ENGINE_CACHE` and template `--cache-dir` overrides still work.
Add the standalone `bin` directory to PATH; the installers do not modify shell
profiles or persistent Windows environment settings.

Changing the resource directory does not move existing binaries or caches.
Old caches remain intact. A first rich build downloads the matching renderer
into the new directory; later `zel build --offline` uses that verified cache.
Existing standalone upgrades update the executable in place. Use the new
installer when intentionally moving an installation to the new default.

Rich file builds continue to need only `zel` installed. Other commands retain
their documented prerequisites. Container runtimes and package managers retain
their own storage locations. This remains a pre-1.0 candidate.
