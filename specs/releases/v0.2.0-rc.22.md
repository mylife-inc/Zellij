## Candidate highlights

- Rich `zel dev` uses an optional verified Next development package by default.
  It needs no separately installed Docker, Node.js, npm or Python. Private Node
  is reused from the existing renderer package; ordinary builds do not download
  the larger development dependencies.
- `zel dev --offline` starts from verified renderer, source and development
  caches. They live under `ZELLIJ_HOME`, defaulting to `~/Dev/config/zellij`.
- Each session owns its generated assets, configuration, Next build files and
  process tree. Valid edits reload the browser; invalid edits retain the last
  successful preparation. Stopping removes the session and preserves downloads.
- `zel dev --dev-backend container` or `ZEL_DEV_BACKEND=container` retains the
  existing container workflow. The explicit flag overrides the environment.

## Compatibility and current limits

This runs Zellij's standard documentation wrapper. Custom Next application code,
plugins and arbitrary npm dependencies still require their own app toolchain.
Cached development serves original image files without Next image optimization.
`zel vw` remains the lighter watched static-preview workflow. Image building and
publishing still need a builder; the optional PDF package is unchanged.

Dependency packages retain their third-party licenses and source references.
The Rust CLI and website engine keep their existing terms. Six native package
and public-download checks are release gates; these notes alone do not certify
publication. Historical timing findings and deferred provider/catalog checks
are not claimed resolved here.
