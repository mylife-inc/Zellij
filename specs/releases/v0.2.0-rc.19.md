## Editable wrappers without extraction prerequisites

Default `zel eject` and `zel new app` now download a small, version-matched
editable-source package into `$ZELLIJ_HOME/cache/sources/<version>/`. They need
no installed Docker, Node/npm or Python to generate an app. Each generated app
has an independent `vendor/zellij` copy; running it still needs Node and npm.

- `--offline` reuses an already verified source cache.
- The interactive app wizard defaults to cached sources; a local engine path
  remains available through `--engine`.
- Explicit `eject --image` and nonempty `ZELLIJ_IMAGE` retain extraction from
  the selected stopped container. `--offline` rejects that explicit image mode.
- The CLI checks archive/file integrity, version, portable paths and limits;
  interrupted downloads do not publish incomplete caches or wrappers.
- Generated CI comments now accurately describe the cached rich-web build
  prerequisites; image/PDF operations retain their tooling requirements.

The new source archive includes engine sources, built helpers, fonts and
license notices. It adds no runtime or dependencies to the small `zel` binary
and is separate from the existing rich-renderer download. PDF, Next development
and image creation retain their documented toolchains. No live provider or
catalog acceptance, stable-1.0 declaration or retirement is included.
